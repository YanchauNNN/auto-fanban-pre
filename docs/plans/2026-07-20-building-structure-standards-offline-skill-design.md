# 建筑结构总图规范离线 Skill 设计

## 目标

以 `documents_bin/规范库.xlsx` 中建筑结构所的 509 条建筑、结构、总图条目为审计基线，建立一套可追溯、可验证、可在内部网络部署的规范问答 Skill。系统必须精确区分规范原文、条文说明、版本状态、替代关系和工程建议，不得在缺少原文证据时依靠模型记忆补全。

## 范围与边界

- 审计全部 509 条记录，但只把来源明确、授权明确的语料纳入离线包。
- 公共官方语料、单位已授权商业语料、内部项目语料分别存放和标记。
- 不绕过登录、验证码、防下载或付费机制，不从第三方盗版站点获取标准或图集。
- `CP`、`JT` 和项目技术规格默认按内部受控资料处理；没有原文件时保留审计记录，不伪造全文。
- 开发机的外部模型需要联网，因此验收拆成：
  1. 本地语料查询与解析在禁用网络时仍可运行；
  2. 网络恢复后，通过真实模型完成网页端到端问答。
- 设计建议必须列出适用标准、条款、项目假设和仍需专业负责人确认的事项，不代替注册工程师或正式审查。

## 方案比较

### 方案一：结构化 SQLite 语料 + 确定性查询（采用）

把标准、章节、条款、表格和页码锚点写入 SQLite，使用标准号精确索引、中文 n-gram/FTS 检索和结构化状态过滤。PDF 或 HTML 原文件只在授权允许时随私有包保存。

优点是可离线、可复核、部署方式与现有 ANSYS Skill 一致，且不依赖向量数据库或外部嵌入服务。缺点是解析和条款结构校验工作较多。

### 方案二：纯向量 RAG

实现较快，但容易把不同版本、条文说明和正文混在一起，难以保证条款号和替代关系准确，不适合作为规范精确问答的唯一方案。

### 方案三：仅保存 PDF，由模型按需阅读

开发成本最低，但查询延迟高、上下文不可控，且表格、页码和跨规范检索难以稳定验证，不满足离线 Skill 的精确性要求。

## 数据分层

### 审计层

每条规范保存：

- 原始编号、规范化编号、名称、部门、专业；
- 标准类别、发布机构、发布日期、实施日期；
- 状态、替代标准、被替代标准；
- 官方信息页、官方全文来源、访问日期；
- 下载能力：自动下载、人工下载、需购买、内部提供、未找到；
- 授权状态：公共官方、单位已授权、授权待确认、禁止纳入；
- 保密等级：公开、内部、受控、待确认；
- 本地文件路径、SHA-256、解析状态、纳入包状态；
- 审计证据和审计备注。

### 语料层

SQLite 至少包含：

- `standards`：标准级元数据和状态；
- `sources`：来源、授权、哈希和文件信息；
- `sections`：章节层级；
- `clauses`：条款号、正文、页码和规范性类型；
- `tables`：表号、标题、结构化单元格和页码；
- `figures`：图号、标题、页码和是否需要视觉核验；
- `relations`：替代、引用和冲突关系；
- `clauses_fts`：中文全文检索索引。

## 获取流程

1. 从规范库读取 509 条目标记录并规范化编号。
2. 根据编号分类路由到国家标准、行业标准、核安全法规、国标图集或内部资料渠道。
3. 先获取元数据和状态，再判断是否允许取得全文。
4. 对允许下载的官方页面保存 URL、访问时间和响应证据。
5. 对付费图集和内部资料只记录获取要求，直到正版文件或内部授权文件到位。
6. 每个本地原文件计算 SHA-256，解析产物通过 manifest 绑定到源文件。

## 解析流程

### PDF

- 使用 PDF 文本层提取字符、页码和坐标。
- 每页保留文本块顺序和来源页码。
- 识别章节、条款号、续表、表号、图号和条文说明。
- 对扫描页或低文本覆盖率页面标记 `ocr_required`，不把空结果当成功。
- 表格同时保存结构化单元格和原页锚点；复杂跨页表格保留视觉复核标记。

### HTML

- 保存官方 HTML 快照和来源 URL。
- 删除导航、脚本和展示噪声，保留标题层级、条款号、表格和脚注。
- 记录 HTML 元素路径和来源页面，保证检索结果可回溯。

## 查询与回答

`standards_query.py` 提供：

- `standard <编号>`：标准元数据、状态和替代关系；
- `clause <编号> <条款号>`：精确条款；
- `search <问题>`：跨规范检索；
- `compare <编号...>`：版本或多规范比较；
- `document <doc_id>`：读取完整结构化记录；
- `health`：离线包完整性与计数检查。

回答策略：

1. 优先识别标准号和条款号。
2. 过滤失效或未授权语料。
3. 获取精确条款全文后再综合。
4. 每个结论引用标准号、名称、版本、条款号和页码。
5. 将规范要求与工程建议分段。
6. 证据不足、版本冲突或图表无法解析时明确停止推断。

## 应用集成

- 新增建筑结构规范 Context Skill handler。
- 在 `documents/AI/参数规范_AI.yaml` 配置根目录、触发词、查询上限和超时。
- 复用安全解压、备份恢复、完整性校验和终端打包模式。
- 私有 ZIP 与原始语料不进入 Git。
- 终端安装目录：

  `D:\FanBanServer\storage\ai\skills\building-structure-standards`

- 环境变量：

  `FANBAN_BUILDING_STANDARDS_SKILL_ROOT`

- AI 探针检查安装完整性、manifest、SQLite 计数和代表性条款查询。

## 测试

- 审计测试：509 条不丢失，编号分类、授权和保密字段完整。
- 解析测试：PDF/HTML 条款、页码、表格和跨页内容。
- 查询测试：精确编号、条款号、中文概念、版本冲突和证据不足。
- 标准答案集：至少 50 条，目标 80 条，覆盖 GB、GB/T、NB/T、JGJ、HAF、图集、JT 和 CP。
- 包验证：manifest、SHA-256、SQLite schema、无越权源文件。
- 集成测试：自动触发、上下文注入、错误传播和跟进问题。
- 部署烟测：`D:\FanBanServer` 安装、离线本地查询、联网模型端到端网页问答。

## 验收条件

- 审计表正好包含 509 条目标记录，所有不确定项显式标记。
- 首版验证集覆盖约 20 项不同来源类型。
- 每个纳入语料都有合法来源、授权状态和哈希。
- 至少 50 条标准答案测试通过。
- 私有 ZIP 可在干净目录安装并通过验证脚本。
- `D:\FanBanServer` 本地 Skill 查询不依赖互联网。
- 真实网页问答可引用标准号、条款号和页码。
- 无法模拟的完全断网模型调用被明确记录为未验证项。

# AI 机器人侧边触发器设计

## 目标

将现有右侧竖排“AI”文字按钮替换为一个扒住页面右侧边框的蓝白 Q 版机器人。机器人提供克制的随机微动，鼠标悬停或键盘聚焦时举手并展示“点我进入AI功能”气泡，点击后继续打开现有 AI 助手抽屉。

本功能仅面向公司内网桌面环境，不考虑手机端或触屏交互。

## 视觉方向

**视觉主张：** 蓝白圆润、友好但不过度卡通的桌面助手，从页面边缘探身并扒住边框，与现有深蓝工程界面保持统一。

- 机器人使用圆角头部、屏幕脸、短手臂和小型天线。
- 身体主体位于页面内，右手表现为扒住浏览器右侧边缘，形成“藏在页面外侧”的空间感。
- 不继续保留竖排“AI”文字框，避免机器人与旧按钮形成双重入口。
- 色彩只复用现有蓝、白、浅青和少量高光色，不引入新的竞争性色系。
- 阴影和高光保持轻量，不能遮挡业务页面的可读内容。

## 内容计划

触发器只承载两个信息层级：

1. 常态：机器人形象本身说明这里是 AI 助手入口。
2. 悬停或键盘聚焦：机器人左侧出现单一气泡“点我进入AI功能”。

不增加副标题、状态徽标或营销用语。

## 交互与动效

**交互主张：** 常态有生命感但不持续干扰，用户靠近时给出明确动作反馈和入口说明。

- 初次出现沿用现有从右侧轻微滑入的入场动画。
- 常态由原生定时器在约 6～14 秒区间随机选择一次微动：眨眼、轻微歪头、身体小幅起伏或天线闪光。
- 任一微动持续时间短，结束后恢复静止；不同时叠加多个随机动作。
- 鼠标悬停或键盘聚焦时立即中止空闲微动，机器人抬起左手挥动，气泡从机器人左侧淡入并轻微上移。
- 鼠标离开或失焦后恢复扒边姿态，重新开始下一轮随机等待。
- 点击机器人调用现有 `handleOpen`，不改变抽屉打开、焦点管理或会话逻辑。
- `prefers-reduced-motion: reduce` 下禁用入场、随机微动和挥手，只保留静态状态与气泡显隐。

## 组件结构

新增 `AiMascotTrigger.tsx`，由 `AiChatDrawer.tsx` 在抽屉关闭状态下渲染。

组件职责：

- 输出语义化 `button`，保留 `aria-label="打开 AI 助手"`。
- 内联绘制 SVG 机器人，使用稳定的 SVG 分组类控制眼睛、头部、身体、手臂和天线动画。
- 管理空闲动画定时器和当前随机动作，不接触聊天数据、网络状态或抽屉尺寸。
- 接收 `onOpen` 回调和现有 `ref`，保持抽屉关闭后的焦点恢复能力。

样式继续放在 `AiChatDrawer.module.css`，但使用独立的 `mascot*` 类名，避免影响抽屉主体。现有另一个 agent 对消息宽度和快速启动的未提交修改必须原样保留；旧 `.collapsedTab` 规则仅在机器人触发器接管后定点替换。

## 内网与桌面兼容性

- 不引用 CDN、远程图片、外部字体、WebGL、Canvas 或第三方动画库。
- 机器人为随组件打包的内联 SVG，所有样式进入现有 Vite 产物，可离线加载。
- 只使用当前桌面 Edge/Chrome 已支持的 SVG、CSS keyframes、`matchMedia` 和原生定时器。
- 不实现手机端媒体查询、触屏专用状态或移动端气泡逻辑。
- 触发器保持足够的桌面点击区域，并限制气泡在视口内，避免覆盖右侧滚动条或被页面裁切。

## 可访问性

- 按钮保持原有可读名称“打开 AI 助手”。
- 键盘 `Tab` 聚焦时获得与鼠标悬停一致的举手和气泡反馈。
- 气泡文本为视觉提示；按钮名称已经表达同一操作，因此气泡不重复进入辅助技术朗读序列。
- 保留清晰焦点环，且机器人动画不改变点击目标的位置。

## 测试与验收

- 组件测试：点击调用 `onOpen`；聚焦显示提示状态；空闲定时器选择动作并在卸载时清理；减少动态效果时不启动随机动画。
- 布局测试：触发器固定在右侧、气泡文本正确、旧竖排 AI 规则不再作为入口。
- 回归测试：现有 AI 抽屉打开、关闭、焦点恢复和会话测试全部通过。
- 完整验证：运行相关 Vitest、全量 `npm test` 和 `npm run build`。
- 桌面实测：在现有开发页面检查 1366×768 和 1600×900 两种桌面视口，确认机器人不遮挡关键操作、气泡不被裁切、随机动作不过于频繁。
- 独立审查：由新的子 agent 对形象美感、动作克制度、提示可理解性和实际点击体验进行审查。

# 计算书逐墙核验紧凑化设计

## 目标

在不丢失逐墙 X/Y/Z 识别证据和人工复核信息的前提下，压缩计算书第二步、第三步的首屏高度，并为“内部编号”提供可直接照填的格式示例。

## 视觉与交互原则

- 视觉命题：工程核验台采用清晰、克制的蓝白信息层级，异常优先，正常证据压缩展示。
- 内容计划：顶部保留任务摘要和异常；中部只显示一次整批 AI 状态；逐墙证据使用紧凑索引；展开后复用现有方向证据卡。
- 交互命题：默认状态可快速扫读，单墙证据按需展开；第三步默认收起整组逐墙证据，避免重复铺满页面。

## 方案选择

采用“公共状态摘要 + 紧凑墙号网格 + 全宽单墙展开”。不采用固定高度内部滚动或虚拟列表，避免在现有可滚动模态框中产生双重滚动；不采用单一主详情面板，避免增加选择状态、焦点同步和额外操作成本。

## 数据与组件边界

1. `documents/参数规范.yaml` 是计算书字段的业务源，为 `internal_code` 增加 `placeholder: "例如：20161NH-JGS01"`。
2. 现有元数据接口、Schema 映射和字段渲染已经支持 `placeholder`，不在 React 组件中硬编码示例。
3. 第二步和第三步继续共用 `ReviewPanel`，新增 AI 模式专用的逐墙紧凑容器：
   - 整批“配筋建议将在任务生成过程中产生”只显示一次。
   - 普通墙体摘要仅显示墙号及方向完整度，不重复完整等待文案。
   - 单墙 `<details>` 展开后横跨网格全部列，继续显示现有 X/Y/Z 方向卡。
4. 第二步默认展示紧凑墙号索引；第三步用外层 `<details>` 默认收起逐墙证据，但人工复核、警告与阻断错误始终显示。
5. 提供配筋表模式保留现有逐墙行号表达，避免影响 Excel 证据可读性。

## 响应式与无障碍

- 桌面端使用自适应多列墙号网格；平板减少列数；手机保持两列并避免横向溢出。
- 继续使用原生 `<details>/<summary>`，支持键盘 Enter/Space 和浏览器固有展开语义。
- 异常状态同时提供文字，不仅依赖颜色。
- 可点击摘要在触控尺寸下保持至少约 44px 高。

## 测试与验收

- 内部编号输入显示 `例如：20161NH-JGS01`。
- AI 模式存在多面墙时，公共等待信息只出现一次。
- 第二步可从紧凑索引展开任意墙体并查看 X/Y/Z。
- 第三步逐墙证据默认收起，展开后仍包含全部墙号和方向证据。
- 提供配筋表模式仍显示配筋表行号。
- 运行针对性 Vitest、完整 `npm test`、`npm run build`，并在桌面和小屏视口进行真实渲染检查。

## RAR 调查边界

本次页面改造不顺带替换部署解压器。已确认真实样本是有效 RAR5，当前部署包却未携带固定 RAR 解压器，实机依赖 `PATH` 中的 `tar.exe`。RAR 的部署级修复应单独包含固定解压器、YAML 路径、部署探针、真实 RAR5 回归和错误分类，避免把环境修复混入纯页面变更。

# 计算书任务集成设计

## 目标

把外部模块 `backend/jisuanshu` 的计算书能力适配为平台原生功能：

- 用户在现有业务模块中填写计算参数并上传一个 ZIP；
- 后端创建独立的异步计算书任务，复用现有任务排队、状态、历史、详情和权限机制；
- 任务严格校验 ZIP、OCR 结果、钢筋选型和模板数据，成功后生成 DOCX；
- 前端在任务详情中展示计算摘要，并提供“下载计算书 DOCX”；
- 部署包携带模板、钢筋表、OCR 运行时和 Python 依赖。

首版只交付 DOCX，不生成 PDF，也不启动 CAD 槽位。

## 已审计的外部模块

外部模块包含两个 Tkinter 入口：

- `main.py`：基础版计算书生成；
- `jinjie.py`：增强版，增加钢筋公称面积表读取、`SM × 1.2` 需求面积计算、配筋选择和边距计算。

适配以 `jinjie.py` 的计算逻辑为基线，但不复用其界面、`os.startfile`、当前目录假设或宽泛异常兜底。模板变量已经与以下两个 Word 模板逐项核对：

- `内部结构计算书.docx`
- `核岛厂房计算书.docx`

钢筋数据来自 `钢筋的公称直径、公称面积表.xlsx`。模块自带 Tesseract 5.5.0，当前仅含英文识别数据；现有识别目标是图中的数字和 `SM` 标记。

## 任务模型与 API

新增任务类型 `calculation_book`，沿用现有 `Job`、队列、事件、状态序列化、权限校验和任务详情。

新增接口：

```text
POST /api/jobs/calculation-books
Content-Type: multipart/form-data
  params_json: JSON 字符串
  archive: 单个 ZIP 文件

GET /api/jobs/{job_id}/download/calculation-book
```

创建成功返回现有任务响应结构。任务产物新增 `calculation_docx`，下载接口只允许访问当前任务记录的最终 DOCX，不能接受调用方传入任意路径。

计算书任务不进入 CAD 执行槽。运行时把它路由到普通文档执行器，并按以下阶段汇报进度：

1. `VALIDATE_ARCHIVE`
2. `OCR_REINFORCEMENT`
3. `SELECT_REBAR`
4. `RENDER_CALCULATION_BOOK`
5. `FINALIZE_ARTIFACT`

任务失败后保留可诊断的阶段和中文错误信息，不生成看似成功的空结果。

## 输入契约

前端提交以下业务字段：

- 模板类型：内部结构 / 核岛厂房；
- 项目代号；
- 项目名称；
- 内部编号；
- 版本；
- 子项代号；
- 子项名称；
- 设计阶段；
- 文件名称；
- 厂房长度、宽度；
- 筏板顶标高、屋面顶标高；
- 历史最低温度、历史最高温度、场地土温；
- 计算图片 ZIP。

项目名称与项目代号使用业务 YAML 枚举和校验规则，版本、阶段、单位和数值范围也以 YAML 为准。项目编号、记录日期、其他厂房列表及可从文件名称可靠推导的数据由后端统一派生，不能由浏览器任意覆盖。

ZIP 必须保留外部模块使用的结构：

```text
计算图片.zip
├── X.*
├── Y.*
├── Z.*
├── 01/
│   └── ...
└── 02/
    └── ...
```

根目录的 X、Y、Z 图片以及 `01`、`02` 目录必须存在。图片扩展名、数量、解压总大小、单文件大小、压缩比和路径安全均由运行期 YAML 限制。

## 严格失败规则

以下情况必须让任务失败：

- ZIP 含绝对路径、父目录穿越、符号链接、设备文件或超限压缩内容；
- ZIP 缺少 X/Y/Z 图片或 `01`、`02` 目录；
- 图片无法读取或 OCR 进程失败；
- 需要识别的图片未得到可信 `SM` 数值；
- 钢筋表缺失、格式错误或没有满足 `SM × 1.2` 的配筋组合；
- 模板缺失、模板变量不完整或 DOCX 渲染失败。

禁止沿用外部 GUI 中“识别失败按 0”“选不到就取最大值”或捕获异常继续生成的兜底。

## 后端结构

外部目录保留为来源和比对依据。生产代码放入 `backend/src/calculation_book/`：

- `models.py`：输入、输出和领域错误；
- `archive.py`：ZIP 安全检查、结构识别和受控解压；
- `ocr.py`：Tesseract 调用和严格数值解析；
- `reinforcement.py`：钢筋表加载与配筋选择；
- `templates.py`：模板选择、上下文构建和变量契约；
- `processor.py`：阶段编排、产物落盘和摘要；
- `executor.py`：与任务运行时的适配层。

模板和钢筋表作为项目业务资产归档到 `documents_bin/calculation_book/`。Tesseract 位置、资产位置、ZIP 限制和 OCR 参数从运行期/机制 YAML 加载；开发环境可以解析外部模块中的现有 Tesseract，部署时必须复制到固定的终端资源目录。

## YAML 归属

- `documents/参数规范.yaml`：计算书业务字段、枚举、必填项和显示文案；
- `documents/参数规范_运行期.yaml`：模板、钢筋表、Tesseract 路径，ZIP/图片大小和数量限制；
- `documents/参数规范-3.yaml`：OCR 阈值、裁剪/识别规则、`SM` 安全系数、配筋选择策略。

代码只提供安全默认值和结构验证，不能把业务参数只写在 Python 常量中。

## 前端信息架构

在现有业务模块的同级操作区增加第四个“计算书”入口，不增加新的顶层模块，也不移动平台标题。

入口打开独立 `CalculationBookWorkspace`：

- 桌面端宽度约 1080–1180px，左侧约 280px 展示 ZIP 上传、必需目录树和校验状态，右侧为分组表单；
- 小屏切换为接近全屏的单列布局；
- ZIP 结构说明始终可见，不依赖悬浮提示；
- 提交时展示校验错误、上传/创建状态，并防止重复提交；
- 弹窗有初始焦点、焦点约束、Escape 关闭和关闭后焦点恢复；
- 所有输入使用真实 `label`，错误、任务状态和进度具有可访问的 `aria` 语义。

任务卡、历史页和详情页沿用现有模式。计算书成功时的主要操作文案统一为“下载计算书 DOCX”，详情展示模板类型、识别图片数、选型摘要和产物文件名。

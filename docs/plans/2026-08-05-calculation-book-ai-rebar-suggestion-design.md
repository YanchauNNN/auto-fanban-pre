# 计算书无实配钢筋 AI 配筋建议设计

日期：2026-08-05
状态：用户已批准

## 1. 背景与目标

计算书任务现有两种配筋来源：标准 Excel 的确定性读取，以及非标准 Excel 触发的 AI 规范化。新增第三种明确模式：用户上传的压缩包不含配筋 Excel，仅包含计算书所需的 `01/02` 图片和结果云图；用户在计算书入口勾选“无实配钢筋”，系统读取云图 SMX，由内网模型通过通用 Skill 给出配筋建议，后端精确复核并直接生成成品 Word。

本功能的目标是：

- 保持现有计算书入口、任务队列、下载方式和 Word 模板体系；
- 将配筋建议能力做成可在内网模型环境独立安装、调用的通用 Skill；
- 首版只使用 SMX，不识别热力分布、颜色面积或连通热点；
- 实际配筋面积不低于 `SMX × 1.10`，并按照已批准的候选优先级尽量减少超额；
- AI 负责通过 Skill 做最终候选选择，后端负责候选精确计算、验算和收敛控制；
- 每个任务生成可下载的独立诊断日志；
- 局部无法生成时保留空白并给出明确提醒，不静默遗漏，也不阻断整份 Word 生成。

## 2. 非目标

首版不做以下事项：

- 不分析云图色带面积、热点比例或连通区域；
- 不允许模型自由编造直径、间距、层数或配筋面积；
- 不根据通用规范自动推断墙厚、保护层、抗震等级等项目设计条件；
- 不改变现有标准 Excel 和非标准 Excel 的处理语义；
- 不增加逐墙网页人工确认或提交后的第二次确认弹窗；
- 不把 Word 模板、项目路径或任务数据库依赖放入通用 Skill。

## 3. 已批准的业务规则

### 3.1 统一需求值

对存在 SMX 的方向：

```text
target_area = SMX × 1.10
```

比较和排序使用未提前舍入的精确值，显示时再按现有计算书格式舍入。

### 3.2 墙体及楼板 X/Y 候选

候选直径：

```text
16, 18, 20, 25, 28, 32, 36, 40
```

硬优先级：

1. 单层 `@200`
2. 单层 `@150`
3. 双层 `@200`
4. 双层 `@150`

在第一个存在合格候选的优先级内，选择实际配筋面积不小于目标值且超额最小的直径。不得为了面积更接近而跳过更高优先级。

线性配筋精确面积：

```text
actual_area = layers × π × (diameter / 2)² × (1000 / spacing)
```

### 3.3 墙体及楼板 Z 候选

候选直径：

```text
6, 8, 10, 12, 14, 16
```

硬优先级：

1. 单层 `400×400`
2. 单层 `200×400`
3. 单层 `200×200`
4. 双层 `400×400`
5. 双层 `200×400`
6. 双层 `200×200`

`400×200` 与 `200×400` 视为同一候选，统一输出为 `200×400`。在第一个存在合格候选的优先级内选择超额最小的直径。

网格配筋精确面积：

```text
actual_area = layers × π × (diameter / 2)² × (1000 / spacing_1) × (1000 / spacing_2)
```

Z 图没有 SMX 时，沿用既有业务规则，将需求视为 0，由 Skill 返回固定构造候选 `1C14@400×400`，后端复核后写入 Word。面积显示单位继续遵循现有计算书已批准的方向与模板约定，本功能不另行改变单位文案。

### 3.4 楼板范围

勾选“包含楼板应力”时：

- TOP、BOTTOM、可选 MIDDLE 的 X/Y 使用第 3.2 节规则；
- 楼板 Z 使用第 3.3 节规则；
- 是否存在 MIDDLE 完全由压缩包文件名决定，不由前端手工选择。

## 4. 方案比较与选择

### 4.1 模型自由计算并输出规格

优点是接入简单且形式上完全由 AI 决定；缺点是面积计算、层数、优先级和输出格式不可稳定复现，无法满足精确验算要求，因此不采用。

### 4.2 后端完全确定规格，AI 只生成说明

可靠性最高，但最终选筋并非由 AI Skill 完成，不符合业务目标，因此不采用。

### 4.3 后端生成合法候选，AI Skill 选择，后端闭环验算

采用此方案。后端负责容易出错但完全确定的数学计算，内网模型通过通用 Skill 做最终候选选择。后端不替代 AI 选择，但会拒绝任何不符合规则的结果，并把针对性错误反馈给同一 Skill 修正，直至通过或触发基础调用失败终止策略。

## 5. 通用 Skill 设计

Skill 名称：`recommend-rebar-from-smx`。

建议目录：

```text
tools/ai/recommend-rebar-from-smx/
├── SKILL.md
├── agents/openai.yaml
├── references/io-schema.md
├── references/ranking-rules.md
└── scripts/validate_fixtures.py
```

Skill 必须满足：

- 不依赖本仓库模块、Excel、Word、任务数据库或外网；
- 可随内网部署包复制到独立 Skill 目录；
- 普通文本模型即可调用，首版不要求多模态能力；
- 只根据结构化 SMX、目标值、候选和修正上下文选择候选；
- 不自行计算或返回新的直径、间距、层数和面积；
- 输出严格 JSON，不输出 Markdown 包裹或额外说明；
- 任何不确定情况必须返回 `needs_review`，不能猜测。

### 5.1 输入协议

每个条目至少包含：

```json
{
  "schema_version": "smx-rebar-1",
  "task_id": "...",
  "items": [
    {
      "item_id": "N5001:Y",
      "member_kind": "wall",
      "member_id": "N5001",
      "direction": "Y",
      "smx": 4756.0,
      "target_area": 5231.6,
      "candidates": [
        {
          "candidate_id": "...",
          "spec": "1D40@200",
          "actual_area": 6283.185307,
          "priority_rank": 1,
          "excess_area": 1051.585307
        }
      ],
      "repair_context": null
    }
  ]
}
```

任务较大时由 Worker 分批调用；批大小放入运行期 YAML。已通过的条目不在修正轮次中重复发送。

### 5.2 输出协议

模型只能返回候选引用：

```json
{
  "schema_version": "smx-rebar-1",
  "items": [
    {
      "item_id": "N5001:Y",
      "status": "selected",
      "selected_candidate_id": "...",
      "reason": "选择最高优先级内满足目标且超额最小的候选",
      "review_reasons": []
    }
  ]
}
```

允许的另一状态为 `needs_review`。模型不能返回候选表中不存在的规格，后端也不能信任模型返回的面积。

## 6. 后端候选与修正闭环

### 6.1 首次调用

1. OCR 读取每张图的 SMX；
2. 后端按 YAML 规则和精确公式生成有限候选集；
3. Worker 调用内网结构化模型并附带 Skill 内容；
4. 模型返回 `candidate_id`；
5. 后端重新计算并验算结果。

### 6.2 验算错误码

- `MARGIN_BELOW_10_PERCENT`：未满足 10% 裕度；
- `PRIORITY_SKIPPED`：跳过了更高优先级；
- `NOT_MINIMUM_EXCESS`：同级存在更小超额候选；
- `INVALID_CANDIDATE`：候选不存在或已排除；
- `FORMULA_MISMATCH`：结构化结果中的派生值与后端精确值不一致；
- `SCHEMA_INVALID`：模型输出不符合协议。

### 6.3 收敛策略

业务验算失败时持续调用 AI 修正：

- 下一轮带上上一轮选择、错误码、错误说明和剩余候选；
- 已判定错误的候选不得再次选择；
- 候选集合单调缩小；
- 最后一轮只保留满足全部规则的最优候选；
- 只重试失败条目，已通过条目保持不变。

模型网关不可访问、超时或持续输出非法 JSON 属于基础调用失败。单个条目连续失败 3 次后停止调用，该方向留空并产生任务提醒。这个次数写入运行期 YAML，不与业务验算修正次数混用。

如果候选集本身没有任何合格组合，直接留空；禁止使用最大规格强行兜底。

## 7. 前端、预检与任务契约

### 7.1 参数模式

新增明确模式字段：

```text
reinforcement_source = provided | ai_suggested
```

“无实配钢筋”复选框映射到 `ai_suggested`，不能通过压缩包是否缺 Excel 隐式推断。该字段进入参数预设；旧预设缺失时默认 `provided`。

### 7.2 压缩包规则

- `provided`：根目录必须且只能存在一个 Excel；
- `ai_suggested`：压缩包必须不存在 Excel；
- 勾选无实配但检测到 Excel 时明确报错，不能静默忽略；
- 两种模式都继续校验压缩包安全、`01/02` 目录和墙体 X/Y/Z 完整性；
- 切换“无实配钢筋”或“包含楼板应力”必须使旧预检令牌失效。

### 7.3 页面流程

- “无实配钢筋”位于上传区域，与“包含楼板应力”紧凑排列；
- 第二步在该模式下显示“云图核验”；
- 展示墙体组数、方向图数、楼板 5/7 组、缺失方向和 Z 零值数；
- 提交按钮正常创建任务，不增加额外 AI 确认弹窗；
- 任务详情显示配筋来源、成功建议数、留空数、修正轮次和日志下载按钮。

## 8. Word 与内部配筋结构

后端把 AI 验算通过的建议转换成与标准配筋表等价的内部 `ReinforcementSchedule`，复用现有图片匹配、裕度表、叙述和 Word 渲染链路。

章节前增加：

> 以下配筋建议由人工智能根据结果云图 SMX 值并保留不低于 10% 的面积裕度生成，供设计人员复核。

正文使用“建议选用钢筋……”而不是冒充已确认实配。仍写入规格、精确面积和包络结论。任务完成后用户直接下载完整成品 Word，无需先在网页逐项确认。

重复语义、`-1/-2` 图组、未知命名、OCR 不可靠、无候选或模型基础调用失败的方向保持空白，并在任务详情中列出原因。字母后缀墙体始终视为独立墙体。

有限元模型图继续来自 `01/02`，不得从应力云图中挑选代替。楼板章节仅按包内实际 TOP/BOTTOM/MIDDLE 分组生成。

## 9. 每任务诊断日志

每个计算书任务生成独立结构化日志，并由任务详情提供下载。建议路径位于任务输出目录的 `logs/calculation-book-<job-id>.log`。

日志至少包含：

- 任务 ID、压缩包 SHA256、参数摘要和图片清单；
- 图片归组、OCR 原始值、SMX 和 Z 零值判定；
- 10% 目标值、精确候选及淘汰原因；
- 每轮 AI 调用的模型、Skill 版本、批次、输入摘要、结构化输出、耗时和错误；
- 后端验算错误码、排除候选和最终结果；
- 写入 Word 的墙号、方向、规格和精确面积；
- 留空方向及人工检查原因；
- 各阶段开始、完成、失败和总耗时。

日志必须脱敏：不记录 API 密钥、Authorization 头、图片 Base64、完整系统提示词或其他秘密配置。服务级日志和任务级日志使用同一关联 ID。

## 10. 错误处理

- OCR 失败：对应方向留空，记录图片和错误；
- 候选为空：留空，记录需求值及候选边界；
- 业务验算失败：进入单调收敛修正循环；
- 模型基础调用连续失败 3 次：留空并告警；
- 局部方向失败不阻断整份 Word；
- 压缩包结构、安全或 `01/02` 缺失属于任务创建前错误；
- 日志创建失败属于任务失败，不能生成一个没有诊断证据的 AI 建议任务。

## 11. 配置归属

业务规则写入 `documents/参数规范-3.yaml`，包括：

- 裕度系数；
- X/Y 和 Z 的直径、间距、层数与优先级；
- Z 零值构造候选；
- 楼板方向到候选 profile 的映射；
- Word 建议说明文本。

运行期配置写入 `documents/参数规范_运行期.yaml`，包括：

- Skill 根目录和版本；
- 模型调用超时；
- 批大小；
- 基础调用最大连续失败次数；
- 每任务日志目录、大小和保留策略。

客户端请求不能覆盖服务器候选规则、Skill 路径或失败次数。

## 12. 测试与验收

### 12.1 Skill 独立验证

- 使用标准初始化结构并通过 Skill 快速校验；
- 在不加载项目代码、Excel或 Word 的环境中处理标准 JSON；
- 使用真实内网模型调用，不只使用 Mock；
- 断网运行，不访问外部接口；
- 记录模型、Skill 版本和内容哈希；
- 使用隔离子 Agent 对原始测试输入进行盲测，避免依赖当前对话。

### 12.2 单元测试

- X/Y 全部直径和四级切换边界；
- Z 全部直径和六级切换边界；
- TOP/BOTTOM/MIDDLE 及 Z 映射；
- 精确公式和 `actual_area >= SMX × 1.10`；
- 第一可行优先级及同级最小超额；
- Z 无 SMX 的固定构造候选；
- 修正错误码、候选排除和单调收敛；
- 三次基础调用失败后的留空；
- 无候选时不兜底。

### 12.3 API、Worker 与前端集成测试

- 两种压缩包模式严格分流；
- 模式变更导致预检令牌失效；
- 普通标准 Excel 不调用新 Skill；
- 非标准 Excel 继续只调用原规范化 Skill；
- 无实配模式只调用新推荐 Skill；
- Worker 分批、局部修正、任务恢复和日志关联；
- 前端复选框、参数预设、云图核验、任务详情和日志下载；
- 1366×768 和 375px 页面无遮挡、无新增不必要滚动；
- 完整前端测试与生产构建通过。

### 12.4 指定真实烟测

固定样本：

```text
E:\project\auto-fanban-pre\test\文档\6层11.45~15\6层11.45~15.95m 结果云图 - 副本.rar
```

SHA256：

```text
B3593CBEB654D8FF3D9350D4C93FBD4311D83F87138B0123CD7816D6BACDE466
```

已确认基线：

- 0 个 Excel；
- 含 `01/02`；
- 184 个图片文件；
- 177 张墙体方向图，组成 59 个墙体组；
- 5 张楼板图；
- 无 MIDDLE。

烟测必须证明：

- 59 个墙体组全部守恒，字母后缀不合并；
- 5 张楼板图生成 TOP/BOTTOM X/Y 和 Z，且不虚构 MIDDLE；
- 每个方向得到有效建议或有明确原因的留空，不能静默遗漏；
- 所有有效建议重新计算后满足 10% 裕度、优先级和最小超额；
- `01/02` 正确进入有限元模型相关章节；
- Word 实际渲染后图片、标题、上角标、分页和表格无错位；
- 任务详情能够下载 Word 和完整任务日志；
- 日志中的图片、调用轮次、验算结果与 Word 条目逐项对应。

### 12.5 内网部署验收

- 部署包包含 Skill、配置、日志入口和所需运行时代码；
- 在无外网条件下启动 API 与 Worker；
- 使用真实内部模型完成指定 RAR 的正式任务流程；
- 报告任务 ID、模型、Skill 哈希、Word 路径、日志路径和任何留空项；
- 如果真实内部模型不可访问，只能报告“代码和 Mock 验证通过，真实模型烟测未完成”，不得声称全部完成。

## 13. 主要风险与控制

- **模型选择不稳定**：候选引用、后端复算、单调收敛修正循环；
- **任务永久卡住**：业务修正与基础调用失败分离，基础调用连续失败 3 次终止；
- **候选规则被客户端篡改**：业务规则只从服务器 YAML 读取；
- **通用 Skill 被项目逻辑污染**：Skill 只定义结构化选择协议，项目适配留在计算书模块；
- **日志泄密或过大**：结构化摘要、敏感字段禁止、运行期大小与保留策略；
- **无表模式破坏旧流程**：显式来源枚举，三种模式分别回归；
- **Word 看似完成但内容遗漏**：方向守恒断言、任务详情统计和日志逐项核对；
- **内部模型环境未实际验证**：真实内网模型烟测作为独立完成门槛。

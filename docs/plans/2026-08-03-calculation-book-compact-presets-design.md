# 计算书创建页紧凑布局与预设设计

## 背景

计算书创建弹窗当前把压缩包说明、目录树、楼板说明、上传区域和全部参数同时展开。桌面端左栏过高，右侧三列表单也占用较多纵向空间，用户需要滚动才能填写完全部参数。同时，计算书尚未提供出图任务已有的配置预设能力，重复任务需要重新录入全部工程和温度参数。

## 目标

- 将上传入口文案改为“上传压缩包”，上传区域使用白色背景。
- 在左栏增加计算书专用预设，支持新建、应用、更新、重命名和删除。
- 在常见桌面视口中尽量无需滚动即可完成全部参数填写。
- 保持现有预检、AI 确认、任务创建、键盘操作和错误定位行为不变。

## 非目标

- 不把压缩包或预检 token 保存进预设。
- 不在后端或账号维度同步预设；语义与现有出图预设一致，保存在当前浏览器。
- 不重构出图任务预设，也不复用其包含出图专用字段的 `TaskConfigPreset` 类型。
- 不修改计算书后端参数、YAML 或生成逻辑。

## 页面结构

### 视觉方向

页面采用紧凑的工程工作台风格：白色操作面、深蓝文字和单一蓝色主操作色。减少卡片层叠与大面积说明文字，以对齐、分组标题和留白建立层级。

### 桌面布局

弹窗输入阶段采用两栏布局：

- 左栏约 240px，依次放置上传压缩包、楼板开关、配置预设、默认折叠的压缩包结构说明。
- 右栏使用四列参数网格；文件名称等宽字段跨两列。
- 页头、步骤条和底部操作栏收紧纵向间距，底部操作栏继续保持可见。
- 输入框目标高度为 38–40px，字段纵向间距约 0.5rem。

在 1366×768 及以上桌面视口中，输入阶段应尽量完整显示；在较窄视口中降为两列或单列并允许滚动，不通过压缩字号牺牲可读性。

### 左栏交互

上传区域的空状态主文案为“上传压缩包”，副文案说明仅支持一个 ZIP/RAR。选择后显示文件名和大小，背景始终为纯白，使用边框、悬停和焦点状态表达可点击性。

压缩包目录树和长说明移入默认折叠的 `<details>`，标题为“压缩包结构要求”。这部分仍可通过键盘访问，且不会在初始视口长期占用高度。

楼板开关保留现有业务说明，但压缩为短说明；完整的 5/7 组规则放入结构说明区域或辅助文本中。

## 预设模型

新增计算书专用预设模块，使用存储键：

```text
auto-fanban.calculation-book-presets
```

单个预设结构：

```ts
type CalculationBookPreset = {
  id: string;
  name: string;
  values: Record<string, string>;
  updatedAt: string;
};
```

保存规则：

- 动态保存当前计算书 schema 中的全部非派生字段，包括 `include_slab_stress`。
- 不保存只读派生字段 `project_name`。
- 不保存压缩包、阶段、预检、错误和忙碌状态。
- 损坏或不兼容的 localStorage 数据安全回落为空列表。
- 预设按 `updatedAt` 倒序显示。

应用规则：

- 只应用当前 schema 仍存在的字段，忽略旧预设中的未知字段。
- 当前 schema 新增但旧预设没有的字段使用当前默认值。
- 下拉值若不再存在于当前选项中，回落为空值或字段默认值。
- 根据 `project_no` 从当前项目枚举重新生成 `project_name`。
- 保留当前已选择的压缩包。
- 清空字段错误和表单错误，并废弃旧预检结果，防止参数与预检 token 不一致。

## 预设界面

左栏预设区域包含：

- 方案名称输入框；
- 已保存方案选择框；
- “保存为新方案”“应用方案”；
- “更新当前方案”“重命名”“删除”；
- 成功提示和就地错误提示。

按钮采用紧凑两列布局。删除和重命名使用次级视觉，避免与上传、预检等主操作竞争。

## 状态与错误处理

- 保存空名称时显示“请先填写方案名称”。
- 应用、更新、重命名或删除前未选择方案时显示明确错误。
- 更新成功后显示“已更新配置”，用户继续编辑时清除该提示。
- 应用预设后将页面恢复到输入阶段；旧预检、证据和确认状态全部失效。
- 预设操作不改变当前压缩包，也不触发上传或后端请求。

## 可访问性

- 所有输入、选择框和按钮都有稳定的可访问名称。
- `<details>` 使用原生键盘交互。
- 上传控件保留可见焦点环。
- 预设成功与错误信息使用 `aria-live`。
- 现有 Escape 关闭、焦点恢复和错误聚焦行为保持不变。

## 验证策略

- 单元测试覆盖预设创建、排序、损坏数据、未知字段过滤、派生项目名称重算和楼板开关恢复。
- 组件测试覆盖保存、应用、更新、删除，验证应用后压缩包仍存在且旧预检失效。
- 组件测试锁定“上传压缩包”文案和默认折叠的结构说明。
- 完整运行计算书组件测试、前端全量 Vitest 和生产构建。
- 使用真实浏览器在 1366×768、1629×1150 和窄屏视口检查首屏高度、上传区白色背景、键盘焦点和响应式布局。
- 由独立页面设计子 Agent 复审美感、密度和操作可发现性。

# 计算书 ZIP / RAR / 7z 安全归档支持设计

## 背景

计算书预检当前使用 Python `zipfile` 处理 ZIP，并把所有非 ZIP 文件交给系统
`tar.exe` 当作 RAR。部署包没有固定的 RAR/7z 解压器，因此目标机 PATH 中的
`tar.exe` 版本不支持 RAR5 时会把有效业务文件误报为无效 RAR；7z 也尚未进入
前端、API、Worker、配置和部署契约。

本次改造在独立 worktree `codex-calculation-archive-formats` 完成，不修改工作量
agent 的工作区，不合并到现有分支。

## 目标与范围

- 接受普通单卷、无密码的 `.zip`、`.rar`、`.7z` 计算书任务压缩包。
- ZIP 保留 Python 标准库实现；RAR 和 7z 使用部署包内固定携带的完整 7-Zip
  运行时。
- API 预检和后台 Worker 使用同一套格式识别、工具路径、超时和安全限制。
- 加密包、分卷包、损坏包、扩展名伪装包给出明确且可诊断的错误，不进入任务。
- 部署机不联网下载、不安装 7-Zip、不写注册表，也不从 PATH 回退到系统工具。
- 保持现有计算书业务内容校验和任务流程不变。

不在本版支持：密码传输与保管、分卷重组、在线插件安装、任意格式自动猜测。

## 方案

### 运行时布局

部署包固定包含：

```text
D:\FanBanServer\bin\7-Zip\
├─ 7z.exe
├─ 7z.dll
├─ License.txt
└─ PROVENANCE.txt
```

构建阶段从经审核的本地依赖缓存取得这些文件，按机制 YAML 中记录的版本和
SHA256 校验后复制。部署包不包含安装器，目标机不执行下载或安装。

### YAML 来源分工

1. `documents/参数规范.yaml`
   - 前端/API 业务白名单：`.zip`、`.rar`、`.7z`。
   - 上传说明和格式文案。
2. `documents/参数规范_运行期.yaml`
   - `calculation_book.archive_extractor.executable`，默认
     `bin/7-Zip/7z.exe`。
   - 列表超时和解压超时。
   - 归档文件数、大小、压缩比继续使用现有运行期配置。
3. `documents/参数规范-3.yaml`
   - 7-Zip 版本、来源、运行时文件清单、各文件 SHA256 和许可证要求。
   - 部署构建与目标机探针只读取该机制配置，不在 Python 或 PowerShell 中重复
     硬编码版本和校验值。

环境变量只作为正式的运行期覆盖入口；默认行为必须能由上述 YAML 完整恢复。

### 格式识别

先读取后缀，再读取文件签名：

- ZIP：`PK` 系列签名。
- RAR4：`52 61 72 21 1A 07 00`。
- RAR5：`52 61 72 21 1A 07 01 00`。
- 7z：`37 7A BC AF 27 1C`。

后缀不在白名单、签名未知或后缀与签名不一致时立即拒绝。禁止把任意非 ZIP
文件继续默认为 RAR。

### 解包流程

```text
上传文件
  -> 后缀/签名识别
  -> ZIP: ZipFile.infolist()
  -> RAR/7z: 固定 7z.exe l -slt
  -> 统一成员安全与资源限制校验
  -> 隔离目录解压
  -> 解压后文件集合/类型/大小复核
  -> 现有计算书内容结构校验
```

RAR/7z 子进程使用参数数组、`shell=False`、`stdin=DEVNULL` 和 YAML 超时；不会
读取 PATH。7-Zip 不存在、版本/哈希不符或格式能力探针失败时采用 fail-closed，
ZIP 仍可由标准库处理，RAR/7z 返回部署环境缺少有效解压组件。

### 安全规则

解压前拒绝：

- 绝对路径、盘符路径、UNC、`..`、控制字符、NTFS ADS。
- Windows 保留设备名、末尾空格或点。
- 按 Windows 大小写不敏感规则发生的重复目标。
- 符号链接、硬链接、重解析点、设备、FIFO 和其他非普通文件。
- 加密条目、分卷归档、空成员名。
- 超过文件/目录数量、单文件大小、总大小或压缩比限制的归档。

解压后重新遍历隔离目录，要求实际普通文件集合和声明清单完全一致，且每个文件
大小一致；出现额外文件、链接、重解析点或超限时删除本次隔离目录并失败。

### 错误与日志

内部使用稳定错误码区分：格式不支持、签名不符、解压器缺失、列表/解压超时、
加密、缺分卷、损坏、不安全成员、资源超限、解压失败和解压后校验失败。

用户只看到安全中文信息。应用日志记录归档 SHA256、大小、识别格式、解压器绝对
路径与版本、退出码和截断后的脱敏错误；不记录业务文件内容或密码。

## 部署构建

- 构建器要求 `7z.exe`、`7z.dll`、`License.txt`、`PROVENANCE.txt` 全部存在且
  与机制 YAML 一致，缺一项即停止构建。
- full/delta 包和 `package-manifest.json` 都记录归档运行时组件与逐文件 SHA256。
- `probe_target_env.ps1` 检查固定路径、版本、ZIP/RAR/7z 格式能力，并实际测试
  三个极小探针包，而非只检查文件存在。
- `prepare_terminal.ps1` 和后端启动脚本只写入/验证固定绝对路径，不安装软件。
- 部署说明包含 7-Zip 许可、来源、诊断命令和不支持加密/分卷的边界。

## 前后端契约

- 前端文件选择器、帮助文本和 schema fallback 同时允许 ZIP/RAR/7z。
- API 后缀、MIME、缓存清理和上传大小逻辑补齐 `.7z`。
- API 预检将归档运行时配置传入验证器；Worker 从同一 RuntimeConfig 读取，避免
  预检成功而后台失败。
- 与压缩格式无关的工作量、账户、任务组和绘图逻辑不改动。

## 验证门槛

1. 单元测试覆盖格式签名、7-Zip 技术列表解析、安全成员、加密/分卷、资源限制、
   缺失工具、超时、退出码和解压后复核。
2. API 测试覆盖 `.7z` 上传、MIME、缓存和错误映射。
3. 前端计算书测试覆盖三格式选择与说明。
4. 部署构建测试覆盖运行时文件、哈希、manifest、脚本和探针。
5. 相同最小业务内容分别打成 ZIP、RAR5、7z，预检结果必须一致。
6. 用户指定真实 RAR 文件走正式 API/Worker 完整生成 Word，并记录任务 ID、产物、
   7-Zip 路径与版本。
7. 在重新生成的 `D:\FanBanServer` 布局再执行三格式探针和真实 RAR 烟测。

只有源码测试、真实样本和部署布局三层均通过，才称为完成。若当前环境缺少经校验
的官方运行时或无法执行目标机部署烟测，应明确报告为剩余风险，不用 mock 代替。

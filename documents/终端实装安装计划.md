# 终端实装安装计划

## 0. 结论

当前版本的终端部署安装命令主流程没有改变。

API / worker 分离属于后端运行模型变化，不增加人工安装步骤：

- 不需要单独启动 worker。
- 不需要手工初始化 SQLite。
- 不需要手工执行 `runtime.env.ps1`。
- `scripts\start_backend.ps1` 会同时托管 API 子进程和 worker 子进程。
- SQLite 队列由后端自动初始化，默认路径是 `D:\FanBanServer\storage\runtime\fanban_queue.sqlite3`。

首次部署仍然按这条主链执行：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\check_iis_proxy_prereqs.ps1
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\install_iis_proxy_prereqs.ps1
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\install_runtime_prereqs.ps1
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\prepare_terminal.ps1
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\deep_check_terminal.ps1
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\configure_iis_site.ps1 -SiteName FanBanTerminal -Port 80
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\register_backend_task.ps1 -UserName "<本机登录账号>"
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\check_health.ps1
```

其中 `install_iis_proxy_prereqs.ps1` 只在 `check_iis_proxy_prereqs.ps1` 显示 URL Rewrite 或 ARR 缺失时必须执行；为减少现场判断成本，首次安装时直接执行也可以。

## 1. 适用场景

本计划适用于终端部署机安装和维护：

- 部署机已安装 AutoCAD。
- 部署机已安装 Office。
- 部署机已安装 IIS，或允许用离线安装包补齐 IIS 反代组件。
- 部署机不能联网。
- 其他客户端通过局域网浏览器访问部署机。
- 后端任务链依赖 Office COM，因此默认使用“用户登录触发”的计划任务，不使用 `LocalSystem` Windows 服务常驻。

默认部署根目录：

```text
D:\FanBanServer
```

如果实际安装目录不是 `D:\FanBanServer`，下文所有命令中的路径必须整体替换。

## 2. 部署包落位

### 2.1 全量包

首次部署，或者不确定目标机当前基线时，使用全量包。

构建机产物可以是目录：

```text
<构建机仓库>\build\fanban-terminal-deploy
```

也可以是 ZIP：

```text
<构建机仓库>\build\fanban-terminal-deploy.zip
```

最终目标机目录必须是：

```text
D:\FanBanServer\frontend-dist
D:\FanBanServer\backend-runtime
D:\FanBanServer\install
D:\FanBanServer\scripts
D:\FanBanServer\documents
D:\FanBanServer\documents_bin
D:\FanBanServer\python-packages
```

如果使用 ZIP，解压时要把 ZIP 中 `fanban-terminal-deploy` 目录里的内容放到 `D:\FanBanServer`。不要形成：

```text
D:\FanBanServer\fanban-terminal-deploy\...
```

### 2.2 局部包

只有目标机当前内容确认匹配上一版全量包时，才可以使用：

```text
<构建机仓库>\build\fanban-terminal-deploy-delta
```

局部包使用规则：

1. 按相同相对路径覆盖到 `D:\FanBanServer`。
2. 按 `_delta\删除清单.txt` 删除旧文件。
3. 覆盖完成后，从“5. 安装和验收步骤”的运行时依赖、环境准备、深度检查和健康检查继续执行。
4. 如果 `_delta\使用说明.txt` 提示未检测到上一版 full 包基线，不要使用局部包，改用全量包。

### 2.3 覆盖升级时保留 storage

覆盖升级时不要随手删除：

```text
D:\FanBanServer\storage
```

这里保存运行状态和历史产物：

- `storage\runtime\fanban_queue.sqlite3`：任务队列、worker 心跳、任务摘要索引。
- `storage\jobs`：任务详情、下载产物、历史结果。

只有明确要清空历史任务、队列状态和产物时，才删除 `storage`。

## 3. 当前后端运行模型

终端后端现在是 API / worker 分离：

```text
FanBanBackend 计划任务
  -> scripts\start_backend.ps1
      -> API 子进程：uvicorn API.app.main:create_app --factory
      -> worker 子进程：python -X utf8 -m API.app.worker
```

各部分职责：

- `FanBanBackend`：登录触发计划任务，只负责启动 supervisor。
- `start_backend.ps1`：加载环境变量、导入预检、启动和看护 API / worker。
- API 子进程：网页接口、任务入队、状态查询、下载接口。
- worker 子进程：CAD、Office 文档生成、纠错、翻版等长任务。
- SQLite 队列：保存队列、worker 心跳、任务摘要，路径为 `storage\runtime\fanban_queue.sqlite3`。

现场注意：

- 不要手工另开 worker。
- 不要注册第二个 worker 计划任务。
- 不要用手工 uvicorn 命令替代正式计划任务，除非只是临时调试。
- `Stop-ScheduledTask -TaskName FanBanBackend` 会停止计划任务；supervisor 退出后会通过 Job Object 结束本次托管的 API 和 worker 子进程。


## 5. 安装和验收步骤

### 5.1 检查 IIS 代理前提

命令：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\check_iis_proxy_prereqs.ps1
```

重点看：

- `iis.installed`
- `url_rewrite.installed`
- `arr.installed`

通过标准：

- IIS 已安装。
- URL Rewrite 已安装。
- ARR 已安装。

如果 URL Rewrite 或 ARR 缺失，执行下一步。

### 5.2 安装 IIS 代理组件

命令：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\install_iis_proxy_prereqs.ps1
```

安装后复查：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\check_iis_proxy_prereqs.ps1
```

三个字段都为已安装后再继续。

### 5.3 安装运行时依赖

命令：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\install_runtime_prereqs.ps1
```

该脚本负责：

- 检查并安装 `.NET Framework 4.8`。
- 检查并安装 `VC++ 2015-2022 x64`。
- 解压部署包内的 Python embeddable runtime。
- 同步 `python-packages` 到 `python-runtime\Lib\site-packages`。

该脚本不安装 NSSM，也不注册 Windows 服务。

### 5.4 准备终端运行环境

命令：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\prepare_terminal.ps1
```

该脚本负责：

- 再次校验运行时依赖。
- 初始化 `storage` 和 `storage\runtime`。
- 探测 AutoCAD、Office、ODA、Resources。
- 生成 `D:\FanBanServer\scripts\runtime.env.ps1`。

正常部署不需要手工点源 `runtime.env.ps1`。正式后端入口 `start_backend.ps1` 会自动加载它，API 和 worker 使用同一份运行环境。

### 5.5 执行深度环境检查

命令：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\deep_check_terminal.ps1
```

输出文件：

```text
D:\FanBanServer\logs\probe_target_env.deep.json
```

通过标准：

- `probe_target_env.deep.json` 已生成。
- blocking issues 为 0。
- Office deep probe 通过。
- AutoCAD、ODA、Resources 检查结果符合当前部署预期。

这一步验证当前登录用户会话里的 Office 能力，不代表 `LocalSystem` 服务态可用。因此正式部署继续使用登录触发计划任务。

### 5.6 配置 IIS 前端站点

推荐先用部署机 IP 访问。

命令：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\configure_iis_site.ps1 -SiteName FanBanTerminal -Port 80
```

脚本会让 IIS 指向：

```text
D:\FanBanServer\frontend-dist
```

如果 URL Rewrite 和 ARR 都已安装，脚本会启用同源 `/api` 反代。

注意：

- 直接按部署机 IP 访问时，不要显式传 `-HostName ""`。
- 如果 `80` 端口被 `Default Web Site` 或其他站点占用，会出现 IIS 绑定冲突，需要先处理端口或站点绑定。
- 如果要用 `8080` 等其他端口，把 `-Port 80` 改成目标端口。

### 5.7 注册后端计划任务

命令：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\register_backend_task.ps1 -UserName "<本机登录账号>"
```

脚本会：

- 清理旧版同名 Windows 服务。
- 注册 `FanBanBackend` 登录触发计划任务。
- 以交互用户令牌运行 `scripts\start_backend.ps1`。
- 如果目标用户当前已登录，尝试立即启动任务。

关键要求：

- `UserName` 必须是实际执行 Office 任务的固定业务账号。
- 该账号需要保持登录状态。
- 不需要也不应该额外注册 worker 任务。

卸载计划任务：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\unregister_backend_task.ps1
```

### 5.8 运行健康检查

命令：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\check_health.ps1
```

重点看：

- 本地环境探针是否通过。
- IIS 代理前提是否通过。
- API ping 是否通过。
- `/api/system/health` 是否 ready。
- `worker_alive` 是否为真。
- `queue_depth` 是否符合当前任务情况。
- `FanBanBackend` 任务状态是否正常。

## 6. 页面访问和烟测

### 6.1 部署机本机访问

浏览器打开：

```text
http://127.0.0.1/
```

或：

```text
http://部署机IP/
```

如果 IIS 绑定端口不是 80，例如 8080：

```text
http://127.0.0.1:8080/
http://部署机IP:8080/
```

### 6.2 局域网客户端访问

同一局域网另一台电脑访问：

```text
http://部署机IP/
```

如果要使用主机名，例如：

```text
http://fanban-server/
```

必须先保证局域网 DNS 或 hosts 能把该主机名解析到部署机 IP。

### 6.3 真实样本烟测

至少用两份固定样本验证：

1. `18185NE-JGS11.dwg`
2. `20261RS-JGS65.dwg`

验收目标：

- 交付任务正常完成。
- 纠错任务正常完成。
- 联合任务正常完成。
- 结果可下载。
- 封面、目录、设计文件、IED 产物符合预期。
- 任务过程中页面不会因为 worker 长任务导致 API 长时间不可用。

## 7. 常规升级流程

### 7.1 只更新前端静态文件

适用范围：

```text
D:\FanBanServer\frontend-dist\...
```

处理方式：

1. 直接覆盖新文件。
2. 浏览器强制刷新：`Ctrl+F5`。
3. 如页面资源缓存仍未更新，执行：

```powershell
iisreset
```

通常不需要停止或重新注册 `FanBanBackend`。

### 7.2 更新后端代码、脚本、模板或规范文件

适用范围包括：

```text
D:\FanBanServer\backend-runtime\...
D:\FanBanServer\documents\...
D:\FanBanServer\documents_bin\...
D:\FanBanServer\scripts\start_backend.ps1
D:\FanBanServer\scripts\runtime.env.ps1
```

处理命令：

```powershell
Stop-ScheduledTask -TaskName FanBanBackend
Get-NetTCPConnection -LocalPort 8000 -State Listen -ErrorAction SilentlyContinue
```

如果第二条没有输出，说明 8000 端口已释放。

然后覆盖新文件到 `D:\FanBanServer`。覆盖时保留：

```text
D:\FanBanServer\storage
```

覆盖完成后执行：

```powershell
Start-ScheduledTask -TaskName FanBanBackend
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\check_health.ps1
```

健康检查通过后，API 和 worker 都已重新加载。

### 7.3 更新 Python 运行时或依赖

适用范围包括：

```text
D:\FanBanServer\python-runtime\...
D:\FanBanServer\python-packages\...
D:\FanBanServer\install\install_runtime_prereqs.ps1
```

处理命令：

```powershell
Stop-ScheduledTask -TaskName FanBanBackend
```

覆盖文件后执行：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\install_runtime_prereqs.ps1
Start-ScheduledTask -TaskName FanBanBackend
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\check_health.ps1
```

### 7.4 什么时候需要重新注册计划任务

通常不需要反复执行 `register_backend_task.ps1`。

只有下面情况建议重新注册：

1. 登录账号变了。
2. 计划任务名变了。
3. 启动路径或启动参数变了。
4. 当前计划任务损坏、被删除或状态异常。
5. 明确要让目标机计划任务定义同步到新版注册脚本。

## 8. 排障顺序

部署或运行异常时，按以下顺序查：

1. `D:\FanBanServer\logs\probe_target_env.json`
2. `D:\FanBanServer\logs\probe_target_env.deep.json`
3. `D:\FanBanServer\scripts\runtime.env.ps1`
4. `D:\FanBanServer\logs\check_health.summary.json`
5. `D:\FanBanServer\logs\check_health.full.json`
6. 任务计划程序中的 `FanBanBackend` 状态和历史记录。
7. API 日志：`D:\FanBanServer\logs\api-stdout-*.log`、`D:\FanBanServer\logs\api-stderr-*.log`
8. worker 日志：`D:\FanBanServer\logs\worker-stdout-*.log`、`D:\FanBanServer\logs\worker-stderr-*.log`
9. supervisor 汇总日志：`D:\FanBanServer\logs\backend-latest-stderr.log`
10. 队列库：`D:\FanBanServer\storage\runtime\fanban_queue.sqlite3`
11. 任务产物：`D:\FanBanServer\storage\jobs`

常见判断：

- 页面打不开：先查 IIS 站点、端口绑定、`frontend-dist`、ARR/URL Rewrite。
- 页面能打开但 API 不通：查 `check_health.ps1`、API stderr、8000 端口监听。
- API 通但任务不动：查 `worker_alive`、worker stderr、SQLite 队列、`storage\jobs`。
- 任务中断或反复重启：查 `backend-latest-stderr.log` 中的 supervisor restart reason。
- CAD 或 Office 异常：优先查 deep probe、`runtime.env.ps1`、worker 日志。

通过标准：

- 部署包 layout 和 manifest 正常。
- 前端以 `frontend-dist` 为准。
- 后端以 `backend-runtime` 为准。
- YAML、`documents`、`documents_bin`、`Resources` 随包携带。
- 不命中开发机绝对路径。
- 不携带 `.lscache`、editable 安装记录、测试覆盖率残留。
- 真实 DWG 冒烟通过后再交付。

## 9.1 本次稳定性更新关注点

- 任务进度刷新同时依赖后端 worker 的运行中摘要同步、`/api/jobs/activity/stream` SSE 推送，以及原 `/api/jobs/activity` 轮询兜底。SSE 不可用时页面仍会继续轮询刷新。
- `documents/参数规范-3.yaml` 中新增 `api_runtime.job_summary_sync_interval_sec`、`api_runtime.jobs_activity_stream_poll_interval_sec`、`api_runtime.jobs_activity_stream_keepalive_sec`，默认分别为 3 秒、2 秒、15 秒。
- `configure_iis_site.ps1` 会把 ARR `system.webServer/proxy` timeout 设置为 `00:10:00`，用于覆盖慢字体预检等可能持续数分钟的同步接口。
- `check_iis_proxy_prereqs.ps1` 和 `check_health.ps1` 会输出 ARR proxy timeout；低于 600 秒时按 warning 处理，需要重新执行 `configure_iis_site.ps1` 或手工修正 IIS ARR proxy timeout。
- Office direct Word/Excel COM 探针失败但后端 export smoke 通过时，会记录到 `info_items`，不计入 warning/blocking；如果 direct COM 和功能 smoke 都失败，仍是 blocking issue。
- `ezdxf DIMASSOC` 警告本轮暂不降噪、不屏蔽、不改变 CAD 裁切链路；只在真实输出异常时另行处理。

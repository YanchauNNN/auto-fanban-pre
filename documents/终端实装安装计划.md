# 终端实装安装计划

## 1. 部署约定

本文面向终端实机部署和维护。默认安装根目录：

```text
D:\FanBanServer
```

如果现场安装目录不同，所有命令中的 `D:\FanBanServer` 必须整体替换。

核心组件：

- 前端静态站点：`D:\FanBanServer\frontend-dist`
- 后端运行目录：`D:\FanBanServer\backend-runtime`
- 安装脚本：`D:\FanBanServer\install`
- 运维脚本：`D:\FanBanServer\scripts`
- 配置和业务资源：`D:\FanBanServer\documents`、`D:\FanBanServer\documents_bin`
- 运行状态和任务产物：`D:\FanBanServer\storage`

后端运行模型：

```text
FanBanBackend 计划任务
  -> scripts\start_backend.ps1
      -> API 子进程：uvicorn API.app.main:create_app --factory
      -> worker 子进程：python -X utf8 -m API.app.worker
```

现场要求：

- 后端使用 `FanBanBackend` 登录触发计划任务，不使用 `LocalSystem` 服务。
- 执行 Office COM 的业务账号必须保持登录状态。
- 不要手工另开 worker。
- 不要注册第二个 worker 计划任务。
- 不要用手工 uvicorn 命令替代正式计划任务，除非只是临时调试。
- 覆盖升级时保留 `D:\FanBanServer\storage`，除非明确要清空历史任务和产物。

## 2. 部署包落位

构建产物可以使用目录包：

```text
<构建机仓库>\build\fanban-terminal-deploy
```

也可以使用压缩包：

```text
<构建机仓库>\build\fanban-terminal-deploy.zip
```

解压或复制后，目标机目录应直接包含：

```text
D:\FanBanServer\frontend-dist
D:\FanBanServer\backend-runtime
D:\FanBanServer\install
D:\FanBanServer\scripts
D:\FanBanServer\documents
D:\FanBanServer\documents_bin
D:\FanBanServer\python-packages
```

其中 `documents` 至少要随包携带同版业务参数文件：

```text
D:\FanBanServer\documents\参数规范.yaml
D:\FanBanServer\documents\参数规范_运行期.yaml
D:\FanBanServer\documents\参数规范-3.yaml
```

如果使用 ZIP，解压时要把 ZIP 中 `fanban-terminal-deploy` 目录里的内容放到 `D:\FanBanServer`。不要形成：

```text
D:\FanBanServer\fanban-terminal-deploy\...
```

局部包 `build\fanban-terminal-deploy-delta` 只适用于目标机明确匹配上一版全量包基线的情况。不能确认基线时，使用全量包。

## 3. 首次安装命令

以管理员 PowerShell 执行。示例端口使用 `8888`；如果现场使用 `80`，只修改 `$FrontendPort`。

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force

$DeployRoot = "D:\FanBanServer"
$SiteName = "FanBanTerminal"
$FrontendPort = 8888
$BackendUser = "<本机登录账号>"

powershell -ExecutionPolicy Bypass -File "$DeployRoot\install\check_iis_proxy_prereqs.ps1"
powershell -ExecutionPolicy Bypass -File "$DeployRoot\install\install_iis_proxy_prereqs.ps1"
powershell -ExecutionPolicy Bypass -File "$DeployRoot\install\install_runtime_prereqs.ps1"
powershell -ExecutionPolicy Bypass -File "$DeployRoot\scripts\prepare_terminal.ps1"
powershell -ExecutionPolicy Bypass -File "$DeployRoot\scripts\deep_check_terminal.ps1"
powershell -ExecutionPolicy Bypass -File "$DeployRoot\install\configure_iis_site.ps1" -SiteName $SiteName -Port $FrontendPort
powershell -ExecutionPolicy Bypass -File "$DeployRoot\install\register_backend_task.ps1" -UserName $BackendUser

$apiReady = $false
$deadline = (Get-Date).AddMinutes(5)
do {
    try {
        Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/system/ping" -TimeoutSec 5 | Out-Null
        $apiReady = $true
    } catch {
        Start-Sleep -Seconds 5
    }
} until ($apiReady -or (Get-Date) -ge $deadline)
if (-not $apiReady) { throw "FanBanBackend API 未在 5 分钟内就绪，请查看 $DeployRoot\logs\backend-latest-stderr.log" }

powershell -ExecutionPolicy Bypass -File "$DeployRoot\scripts\check_health.ps1"
```

`$BackendUser` 必须是实际登录并执行 Office COM 的固定业务账号，例如：

```powershell
$BackendUser = "wangrca"
```

## 4. 安装步骤说明

### 4.1 IIS 代理组件

先检查：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\check_iis_proxy_prereqs.ps1
```

如果 IIS、URL Rewrite 或 ARR 缺失，执行：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\install_iis_proxy_prereqs.ps1
```

安装后重新执行检查脚本，确认 IIS、URL Rewrite、ARR 均可用。

### 4.2 运行时依赖

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\install_runtime_prereqs.ps1
```

该脚本负责 `.NET Framework 4.8`、VC++ 运行库、Python embeddable runtime 和 Python 包同步。

### 4.3 终端环境准备

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\prepare_terminal.ps1
```

该脚本会初始化 `storage`，探测 AutoCAD、Office、ODA、资源文件，并生成：

```text
D:\FanBanServer\scripts\runtime.env.ps1
```

正常部署不需要手工点源 `runtime.env.ps1`。

当前版本的 `start_backend.ps1` 还会在启动 uvicorn 前校验 `FANBAN_SPEC_PATH`、`FANBAN_RUNTIME_SPEC_PATH`、`FANBAN_MECHANISM_SPEC_PATH` 三个 YAML 路径，并把实际使用的路径写入后端日志。如果这三个路径无效，或者 `API.app.main` 导入失败，启动脚本会在真正拉起 uvicorn 前失败，并在 `logs\backend-latest-stderr.log` 中写出明确原因。

### 5.5 执行深度环境检查

命令：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\deep_check_terminal.ps1
```

输出文件：

```text
D:\FanBanServer\logs\probe_target_env.deep.json
```

通过标准：

- deep probe JSON 已生成。
- blocking issues 为 0。
- AutoCAD、Office、ODA、Resources 检查结果符合现场预期。

### 4.5 IIS 前端站点

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\configure_iis_site.ps1 -SiteName FanBanTerminal -Port 8888
```

如果现场使用 80 端口：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\configure_iis_site.ps1 -SiteName FanBanTerminal -Port 80
```

该脚本会配置：

- IIS 站点指向 `D:\FanBanServer\frontend-dist`
- 同源 `/api` 反代到 `127.0.0.1:8000`
- ARR proxy timeout 为 10 分钟
- `FanBanTerminalAppPool` 常驻

常驻设置不影响手工停止后端计划任务。它只避免 IIS 前端因空闲而自动停止或回收。

### 4.6 后端计划任务

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\register_backend_task.ps1 -UserName "<本机登录账号>"
```

脚本会注册 `FanBanBackend` 登录触发计划任务，并在目标账号已登录时尝试立即启动。

首次安装后不要再额外执行 `Start-ScheduledTask -TaskName FanBanBackend`，除非上一步明确没有启动成功。

## 5. 健康验收

命令：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\check_health.ps1
```

重点看：

- `Overall status`
- `Frontend AppPool`
- `Frontend HTTP`
- `Frontend API proxy`
- `API ping`
- `API health`
- `Backend listener`
- `Scheduled task`
- `IIS proxy timeout`

通过标准：

- `Overall status` 为 `pass`。
- `Frontend AppPool` 为 `pass`。
- `Frontend HTTP` 为 `pass`。
- `Frontend API proxy` 为 `pass`。
- `API ping` 为 `pass`。
- `API health` 为 `pass`。
- `Backend listener` 至少有 1 个监听。
- `IIS proxy timeout` 不低于 600 秒。

`check_health.ps1` 会自动从 `FanBanTerminal` 的 IIS 绑定推导本机前端 URL。必要时可以手工指定：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\check_health.ps1 -FrontendUrl "http://127.0.0.1:8888/" -FrontendApiPingUrl "http://127.0.0.1:8888/api/system/ping"
```

## 6. 页面访问

部署机本机访问：

```text
http://127.0.0.1:8888/
```

局域网客户端访问：

```text
http://部署机IP:8888/
```

如果现场使用 80 端口，则访问：

```text
http://127.0.0.1/
http://部署机IP/
```

如果使用主机名，必须先保证局域网 DNS 或 hosts 能把该主机名解析到部署机 IP。

## 7. 常用启停命令

停止后端 API 和 worker：

```powershell
Stop-ScheduledTask -TaskName FanBanBackend
Start-Sleep -Seconds 5
Get-NetTCPConnection -LocalPort 8000 -State Listen -ErrorAction SilentlyContinue
```

如果最后一条没有输出，说明后端端口已释放。

启动后端 API 和 worker：

```powershell
Start-ScheduledTask -TaskName FanBanBackend
```

只重启 IIS 前端：

```powershell
Restart-WebAppPool -Name FanBanTerminalAppPool
```

停止 IIS 前端：

```powershell
Stop-WebAppPool -Name FanBanTerminalAppPool
Stop-Website -Name FanBanTerminal
```

启动 IIS 前端：

```powershell
Start-WebAppPool -Name FanBanTerminalAppPool
Start-Website -Name FanBanTerminal
```

## 8. 常规升级

### 8.1 只更新前端

覆盖范围：

```text
D:\FanBanServer\frontend-dist
```

处理：

```powershell
Restart-WebAppPool -Name FanBanTerminalAppPool
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\check_health.ps1
```

通常不需要停止或重新注册 `FanBanBackend`。

### 8.2 更新后端、脚本、模板或规范文件

覆盖范围通常包括：

```text
D:\FanBanServer\backend-runtime
D:\FanBanServer\documents
D:\FanBanServer\documents_bin
D:\FanBanServer\scripts
```

处理：

```powershell
Stop-ScheduledTask -TaskName FanBanBackend
Get-NetTCPConnection -LocalPort 8000 -State Listen -ErrorAction SilentlyContinue
```

确认 8000 端口释放后覆盖文件。覆盖完成后：

```powershell
Start-ScheduledTask -TaskName FanBanBackend
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\check_health.ps1
```

### 8.3 更新 Python 运行时或依赖

覆盖范围：

```text
D:\FanBanServer\python-runtime
D:\FanBanServer\python-packages
D:\FanBanServer\install\install_runtime_prereqs.ps1
```

处理：

```powershell
Stop-ScheduledTask -TaskName FanBanBackend
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\install_runtime_prereqs.ps1
Start-ScheduledTask -TaskName FanBanBackend
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\scripts\check_health.ps1
```

### 8.4 需要重新执行 IIS 配置的情况

以下情况执行：

```powershell
powershell -ExecutionPolicy Bypass -File D:\FanBanServer\install\configure_iis_site.ps1 -SiteName FanBanTerminal -Port 8888
```

需要重新配置 IIS 的情况：

- 首次部署。
- IIS 站点被删除、损坏或端口绑定变化。
- 前端目录变化。
- 部署包中的 IIS 反代或 AppPool 策略变化。
- `check_health.ps1` 提示 `Frontend AppPool`、`Frontend HTTP`、`Frontend API proxy` 或 ARR timeout 异常。

### 8.5 需要重新注册后端计划任务的情况

通常不需要反复执行 `register_backend_task.ps1`。

只有以下情况需要重新注册：

- 登录账号变化。
- 计划任务被删除或损坏。
- 启动路径或启动参数变化。
- 需要同步新版计划任务定义。

## 9. 烟测

至少用固定 DWG 样本验证：

1. 交付任务正常完成。
2. 纠错任务正常完成。
3. 联合任务正常完成。
4. 结果可下载。
5. 封面、目录、设计文件、IED 产物符合预期。
6. 长任务运行时页面不会持续断连。

其中 `backend-latest-stderr.log` 是排查后端无法启动的首要日志。重点看：

- `backend-env: FANBAN_SPEC_PATH=...`
- `backend-env: FANBAN_RUNTIME_SPEC_PATH=...`
- `backend-env: FANBAN_MECHANISM_SPEC_PATH=...`
- `backend-start-cwd: ...`
- `backend-command: ...`
- `backend-import-preflight-ok`
- `后端启动环境变量无效`
- `后端导入预检失败`

常见判断：
建议保留两份固定样本：

```text
18185NE-JGS11.dwg
20261RS-JGS65.dwg
```

## 10. 排障顺序

优先收集：

```text
D:\FanBanServer\logs\check_health.summary.json
D:\FanBanServer\logs\check_health.full.json
D:\FanBanServer\logs\probe_target_env.deep.json
D:\FanBanServer\logs\backend-latest-stderr.log
D:\FanBanServer\logs\api-stderr-*.log
D:\FanBanServer\logs\worker-stderr-*.log
D:\FanBanServer\storage\runtime\fanban_queue.sqlite3
D:\FanBanServer\storage\jobs
```

判断顺序：

- 页面打不开：查 `Frontend HTTP`、IIS 站点、端口绑定、`frontend-dist`。
- 页面能打开但 API 不通：查 `Frontend API proxy`、ARR/URL Rewrite、8000 后端监听。
- API 直连 8000 不通：查 `FanBanBackend` 计划任务、API stderr、supervisor 日志。
- 任务不执行：查 worker stderr、队列库、worker 心跳。
- 任务反复中断：查 `backend-latest-stderr.log` 中的 supervisor restart reason。
- CAD 或 Office 异常：查 deep probe、`runtime.env.ps1`、worker 日志。

## 11. 构建机交付前检查

构建：

```powershell
uv run --project backend python tools/build_terminal_deploy.py
```

测试：

```powershell
uv run --project backend pytest backend/tests/unit/test_terminal_deploy_builder.py
```

打包卫生检查：

```powershell
rg -n "E:\\project|E:/project|auto-fanban-pre" build\fanban-terminal-deploy\scripts build\fanban-terminal-deploy\backend-runtime build\fanban-terminal-deploy\frontend-dist build\fanban-terminal-deploy\install
rg --files build\fanban-terminal-deploy\backend-runtime build\fanban-terminal-deploy\scripts build\fanban-terminal-deploy\install -g "*.lscache" -g "direct_url.json" -g "_auto_fanban.pth" -g "_editable_impl_auto_fanban.pth" -g "a1_coverage.pth" -g ".build_packages/**"
Get-ChildItem build\fanban-terminal-deploy\backend-runtime,build\fanban-terminal-deploy\scripts,build\fanban-terminal-deploy\install -Recurse -Force | Where-Object { $_.Name -eq "__pycache__" -or $_.Extension -eq ".pyc" }
```

交付标准：

- 构建成功。
- 单元测试通过。
- 前端以 `frontend-dist` 为准。
- 后端以 `backend-runtime` 为准。
- YAML、`documents`、`documents_bin`、`Resources` 随包携带，且 `documents/参数规范.yaml`、`documents/参数规范_运行期.yaml`、`documents/参数规范-3.yaml` 与部署包同版。
- 不命中开发机绝对路径。
- 不携带 `.lscache`、editable 安装记录、测试覆盖率残留。
- 真实 DWG 冒烟通过后再交付。

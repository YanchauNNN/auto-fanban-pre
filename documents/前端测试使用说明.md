## 3. 启动前准备

建议开两个终端，工作目录分别切到：

```text

E:\project\auto-fanban-pre\frontend
```

注意：

- 只要后端代码、YAML 或模板有变更，联调前请先重启 API。
- 如果页面表现像旧版本，第一反应先确认前端是否连到了正确的 API。
- 当前前端业务模块依赖 `/api/system/health` 与 `/api/meta/form-schema`；这两个接口任何一个异常，首页主按钮都会进入不可提交状态。

## 4. 启动命令

### 4.1 启动后端 API

```powershell
cd E:\project\auto-fanban-pre
uv run --project backend python -m uvicorn API.app.main:app --host 127.0.0.1 --port 8000
```

健康检查地址：

```text
http://127.0.0.1:8000/api/system/health
```

正常情况下至少应看到：

- `ready: true`
- `storage_writable: true`
- `worker_alive: true`

### 4.2 启动前端

```powershell
cd E:\project\auto-fanban-pre\frontend
npm run dev -- --host 127.0.0.1 --port 5173
```

前端地址：

```text
http://127.0.0.1:5173
```

默认 API 地址：

```text
http://127.0.0.1:8000
```

如需改 API 地址：

```powershell
cd E:\project\auto-fanban-pre\frontend
$env:VITE_API_BASE_URL="http://你的API地址"
npm run dev -- --host 127.0.0.1 --port 5173
```

### 4.3 端口占用排查

如果后端启动时报 `WinError 10048`，可先执行：

```powershell
Get-NetTCPConnection -LocalAddress 127.0.0.1 -LocalPort 8000 -State Listen |
Select-Object LocalAddress, LocalPort, State, OwningProcess
```

再用返回的 `OwningProcess` 查询进程：

```powershell
Get-CimInstance Win32_Process -Filter "ProcessId=<PID>" |
Select-Object ProcessId, ParentProcessId, Name, ExecutablePath, CommandLine | Format-List
```

确认是旧的 `uvicorn` / `API.app.main` 进程后，再安全关闭。

## 6. 基本操作流程

### 6.1 出图

1. 打开首页，确认 `业务模块` 已选中。
2. 点击 `出图`。
3. 在系统文件选择器中选中一个或多个 `.dwg`。
4. 打开 `任务配置` 弹窗。
5. 系统会先执行一次字体预检。
6. 若字体全部正常，直接继续填写配置。
7. 若存在缺失字体，会弹出“缺失字体处理”弹窗，要求按缺失类型选择替代字体。
8. 填写业务参数后点击创建。

当前出图配置页已经具备的能力：

- 基于 `form-schema` 渲染主参数
- 高级选项折叠/展开
- 本地草稿恢复
- 配置方案保存 / 应用 / 更新 / 重命名 / 删除
- `runAuditCheck` 联动开关
- `plot_style_key` 打印样式选择

当前 `plot_style_key` 可选值：

- `red_wider`
- `same_width`
- `review_white`

当前“次级任务开关”规则：

- 未勾选纠错：只创建交付任务
- 勾选纠错：一次提交 `POST /api/jobs/batch`，并带 `run_audit_check=true`
- 后端会直接创建一个 `TaskGroup`，包含 `deliverable_main + audit_check` 两个子任务

### 6.2 纠错

1. 点击首页 `纠错`。
2. 选择 `.dwg`。
3. 在纠错弹窗中确认 `project_no`。
4. 提交后创建 `mode=check` 的纠错任务。

当前纠错弹窗是最小配置：

- `project_no`
- `files[]`

说明：

- `project_no` 会优先参考文件名推断结果。
- 关闭弹窗不会丢掉草稿。

### 6.3 翻版

1. 点击首页 `翻版`。
2. 选择翻版模式：
   - `仅翻版`
   - `同步出图和翻版`
3. 上传 `.dwg`
4. 填写：
   - `source_project_no`
   - `target_project_no`
5. 提交

当前真实行为：

- `仅翻版`
  - 直接调用 `POST /api/jobs/audit-replace`
  - `mode=replace`
  - `run_deliverable=false`
- `同步出图和翻版`
  - 先采集翻版参数
  - 再进入现有出图配置弹窗
  - 最终提交 `mode=replace`
  - `run_deliverable=true`
  - 出图参数整体写入 `deliverable_params`

### 6.4 任务详情与下载

当前详情页会按任务类型展示下载按钮：

- 交付任务：
  - `下载 package.zip`
  - `下载 IED计划.xlsx`
- 纠错任务：
  - `下载 report.xlsx`
- 翻版任务：
  - `下载 replaced.dwg`
- group 任务：
  - 由后端聚合展示可下载产物

如果是 group：

- 交付 + 纠错：展示两个 child
- 翻版 + 出图：展示两个 child

## 7. 当前应重点检查的行为

### 7.1 首页与模块切换

- `业务模块` 可正常操作
- `账号模块` 仍显示占位，不应误认为已接通
- `工作量模块` 仍显示占位，不应误认为已接通
- 健康检查异常时，首页主入口应进入不可提交状态

### 7.2 出图

- 文件上传后会自动触发字体预检
- 缺失字体时会弹替代字体确认窗
- 字体全正常时，不应强制多弹一步
- `runAuditCheck` 打开后，创建结果应变成 group，而不是两个独立任务
- `plot_style_key` 能进入提交结果，并在详情页返回

### 7.3 纠错

- 仅要求 `project_no + files[]`
- 提交后任务类型应显示为纠错链
- 详情页应展示 `findings_count / affected_drawings_count / top_wrong_texts`

### 7.4 翻版

- `source_project_no` 为空时报错
- `target_project_no` 为空时报错
- 两者相同时报错
- `仅翻版` 时应返回翻版任务
- `同步出图和翻版` 时应返回 group

### 7.5 草稿与方案

- 出图关闭后重新打开可恢复草稿
- 翻版关闭后重新打开可恢复源/目标项目号与模式
- 配置方案不保存上传文件
- 提交成功后草稿应清空

## 9. 常见排错

### 9.1 页面像旧版本

优先检查：

- 后端 API 是否已重启
- 前端是否连接到了正确的 `VITE_API_BASE_URL`
- 浏览器是否还停留在旧 dev server

### 9.2 主按钮不可用

优先检查：

- `/api/system/health` 是否返回 `ready=true`
- `/api/meta/form-schema` 是否成功返回

### 9.3 下载按钮是灰色

优先检查：

- 该任务是否真的已完成
- `job.json / group.json` 中对应 artifact 是否存在
- 详情页 `flags / errors` 是否有失败信息

### 9.4 字体替代窗没有弹出

不要先默认是前端没接。

要先判断两种情况：

- 后端真的没查到缺失字体
- 用户上传的样本已经被改过，后端判断为 `ok`

### 9.5 Word 弹出保存提示

这通常不是当前任务本身失败，而是本机残留的 `WINWORD.EXE` 进程导致的历史弹窗。

优先处理：

- 关闭残留 Word 窗口
- 确认没有手工打开未保存模板
- 再重新做 smoke

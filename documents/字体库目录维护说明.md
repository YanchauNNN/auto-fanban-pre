# 字体库目录维护说明

更新时间：2026-04-07

## 1. 目标

这份说明只解决一件事：

- 当 DWG 里的原始字体在 AutoCAD 自带 `Fonts` 目录和系统字体里都找不到时，团队应该如何补齐字体库，以及如何维护默认替代规则。

目标不是“让某一张图不报错”，而是让后续类似问题都能按同一条链处理。

## 2. 当前后端的字体处理顺序

后端现在按下面的优先级处理字体问题：

1. **原字体直命中**
   - AutoCAD 自带 `Fonts`
   - Windows 系统字体
   - `font_library_dirs` 指向的团队字体库目录

2. **缺失字体名精确映射**
   - 例如：
     - `MENU2.TTF -> simsun.ttc`

3. **按字体类型兜底**
   - `ttf -> default_ttf_families`
   - `shx -> default_shx_fonts`
   - `bigfont -> default_bigfont_fonts`

也就是说：

- 最优先的方案永远是**让 AutoCAD 直接找到原字体**
- 如果原字体找不到，再用“已验证有效”的替代映射
- 只有前两层都没命中，才走 kind 级默认兜底

## 3. 字体库目录配置在哪里

运行期配置在：

- [参数规范_运行期.yaml](E:\project\auto-fanban-pre\documents\参数规范_运行期.yaml)

当前相关配置：

- `runtime_options.font_preflight.font_library_dirs`
- `runtime_options.font_preflight.preferred_replacements_by_missing_font`
- `runtime_options.font_preflight.default_ttf_families`
- `runtime_options.font_preflight.default_shx_fonts`
- `runtime_options.font_preflight.default_bigfont_fonts`
- `runtime_options.font_preflight.default_fontalt_by_kind`

## 4. 什么时候应该补字体库

遇到以下情况时，优先补字体库，不要先去写新的替代规则：

1. 预检明确报缺失字体
   - 例如 `MENU2.TTF`
   - 并且这类字体后续大概率还会在别的图里继续出现

2. 该字体具有明显的项目习惯或供应链来源
   - 某家设计院
   - 某家设备厂家
   - 某类历史图纸

3. 替代后排版虽然可读，但版式仍不稳定
   - 字间距不对
   - 宽度不对
   - 局部仍出现问号或错位

判断原则：

- **能补原字体，就先补原字体**
- 替代字体应该是第二选择，不是第一选择

## 5. 什么时候应该补“精确映射”

只有在下面这种情况下，才推荐新增：

- `preferred_replacements_by_missing_font`

适用场景：

1. 原字体拿不到
2. 已经验证某个替代字体在真实样本上稳定有效
3. 这种缺失字体未来很可能重复出现

当前已经验证有效的一条是：

```yaml
preferred_replacements_by_missing_font:
  default:
    "MENU2.TTF": "simsun.ttc"
```

这条的含义是：

- 当缺失字体名正好是 `MENU2.TTF`
- 并且原字体库没有命中
- 后端默认推荐 `simsun.ttc`

## 6. 已落地的字体库目录

当前仓库里已经正式落地下面这组目录：

- `E:\project\auto-fanban-pre\documents_bin\font-library`
- `E:\project\auto-fanban-pre\documents_bin\font-library\ttf`
- `E:\project\auto-fanban-pre\documents_bin\font-library\shx`
- `E:\project\auto-fanban-pre\documents_bin\font-library\notes`

目录职责固定为：

- `ttf/`
  - 团队补充的 `ttf / ttc / otf`
- `shx/`
  - 团队补充的 `shx / bigfont`
- `notes/`
  - 来源说明和维护记录

运行期 YAML 现在默认启用这两条路径：

```yaml
font_library_dirs:
  - "documents_bin/font-library/ttf"
  - "documents_bin/font-library/shx"
```

`notes/` 下约定维护记录文件名为：

- `来源说明.md`

## 7. 目录维护要求

### 7.1 字体文件怎么放

- `ttf/` 只放 `ttf / ttc / otf`
- `shx/` 只放 `shx / bigfont`
- 不要把截图、压缩包、Excel、说明文档混放进字体目录

### 7.2 来源说明至少记录什么

每次新补字体，建议至少记录：

- 字体文件名
- 来源图纸或来源单位
- 谁补充的
- 为什么需要补
- 是否有许可证/可内部分发风险

这样后面团队就不会只记得“某次好像用过这个字体”。

## 8. 维护流程建议

遇到新的缺失字体时，建议按下面顺序处理：

1. 先跑预检，确认缺失字体名和 `kind`
2. 在团队字体库中查是否已有原字体
3. 如果没有：
   - 找原始字体文件
   - 放入字体库目录
   - 在 `notes/来源说明.md` 记录来源
4. 如果确实拿不到原字体：
   - 用真实样本验证一个可接受的替代字体
   - 把映射写进 `preferred_replacements_by_missing_font`
5. 再用真实样本重新跑一次：
   - `preflight`
   - `split-only` 或完整交付 smoke

## 9. 不推荐的做法

不要这样做：

1. 看到缺字体就直接换成任意 SHX
2. 不做验证就把某个字体写成全局默认
3. 把某张图的临时结论写死进代码
4. 只修改前端默认值，不更新后端 YAML 事实源

这些做法都容易导致：

- 这张图好了
- 下一张图又坏
- 团队没人知道为什么会这样

## 10. 当前团队默认结论

- 缺失字体：`MENU2.TTF`
- 默认替代：`simsun.ttc`

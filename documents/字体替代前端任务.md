# 字体替代前端任务

## 目标

在交付模块提交 DWG 前，先调用后端字体预检接口。
如果发现缺失字体，则弹窗提示用户选择一个替代字体，再继续正式提交任务。

## 新增交互流程

1. 用户选择一个或多个 DWG。
2. 前端先调用 `POST /api/jobs/preflight-fonts`。
3. 如果所有文件都返回 `status = ok`，则按现有流程直接调用 `POST /api/jobs/batch`。
4. 如果任一文件返回 `status = missing_fonts`，则弹出“缺失字体处理”弹窗。
5. 用户在弹窗中选择一个替代字体后，再调用 `POST /api/jobs/batch`。
6. 任务详情页展示字体预检与替代摘要。

## 新增接口

### `POST /api/jobs/preflight-fonts`

请求：

- `multipart/form-data`
- 字段名：`files[]`
- 支持单文件和多文件

示例响应：

```json
{
  "files": [
    {
      "filename": "19163RC-JGS04-WD.dwg",
      "status": "missing_fonts",
      "missing_fonts": [
        {
          "style_name": "HZTXT",
          "font_name": "missing.shx",
          "bigfont_name": "",
          "kind": "shx",
          "used_in_block": true
        }
      ],
      "detected_style_count": 30,
      "missing_style_count": 1,
      "font_replacement_applied": false,
      "replacement_font": null,
      "replaced_style_count": 0
    }
  ],
  "replacement_options": [
    {
      "label": "simplex.shx (AutoCAD SHX)",
      "value": "simplex.shx",
      "family": "simplex",
      "path": "D:\\Program Files\\AUTOCAD\\AutoCAD 2022\\Fonts\\simplex.shx",
      "kind": "shx",
      "source": "autocad_fonts"
    }
  ],
  "requires_confirmation": true
}
```

### 字段说明

#### `files[].status`

- `ok`：当前文件未发现缺失字体
- `missing_fonts`：发现缺失字体，需要用户确认替代字体
- `failed`：预检失败，前端应展示错误并阻止正式提交

#### `files[].missing_fonts[]`

- `style_name`：缺失字体对应的文字样式名
- `font_name`：样式当前字体文件名
- `bigfont_name`：样式当前大字体文件名
- `kind`：`shx` / `ttf` / `bigfont` / `unknown`
- `used_in_block`：该缺失字体是否出现在块内、嵌套块或属性文字使用链中

#### `replacement_options[]`

- `label`：前端下拉显示名
- `value`：正式提交时传给后端的字体值
- `family`：字体族名
- `path`：工作站字体路径，仅用于调试展示，不建议作为主文案
- `kind`：候选字体类型，当前会优先返回 `shx`
- `source`：候选来源，优先为 `autocad_fonts`

### 候选字体来源与排序

- 后端会优先从 AutoCAD 实机探测到的 `Fonts` 目录收集 `*.shx`
- 当预检结果缺失类型为 `shx` / `bigfont` 时，`replacement_options` 会优先返回 SHX 候选
- 只有缺失类型为 `ttf`，或当前机器未探测到任何 SHX 候选时，才会回退到 Windows TrueType 字体

## 正式提交参数变更

### `POST /api/jobs/batch`

在现有 `params_json` 基础上新增两个字段：

- `font_replace_policy`
- `font_replacement_font`

#### `font_replace_policy`

可选值：

- `none`
- `replace_missing`

#### `font_replacement_font`

- 当 `font_replace_policy = replace_missing` 时必填
- 值必须来自 `replacement_options[].value`

示例：

```json
{
  "project_no": "1916",
  "font_replace_policy": "replace_missing",
  "font_replacement_font": "simplex.shx"
}
```

## 前端弹窗要求

### 弹窗展示内容

1. 文件名
2. 缺失字体条目列表
3. 当前工作站可选替代字体下拉
4. 提示文案：
   - 只会修改任务工作副本
   - 不会修改原始上传文件
   - 替代只作用于缺失字体样式
   - 对 SHX 缺失，候选会优先来自 AutoCAD `Fonts` 目录

### 弹窗操作

1. `取消`
   - 不提交任务
2. `继续提交`
   - 只有用户选定替代字体后才允许点击
   - 提交时带上：
     - `font_replace_policy = replace_missing`
     - `font_replacement_font = 下拉选中值`

## 错误处理

### 预检阶段

如果 `files[].status = failed`：

- 阻止正式提交
- 展示文件级错误
- 优先展示 `errors[]`

### 正式提交阶段

如果后端返回 422：

- `font_replace_policy = replace_missing` 但未传字体
- 或传了无效字体
- 前端按普通表单错误处理即可

## 任务详情页新增展示字段

`GET /api/jobs/{id}` 新增：

- `font_preflight_summary`
- `missing_fonts_detected`
- `font_replacement_applied`
- `replacement_font`
- `replaced_style_count`

推荐展示方式：

1. 若 `missing_fonts_detected = false`
   - 展示“未检测到缺失字体”
2. 若 `missing_fonts_detected = true` 且 `font_replacement_applied = false`
   - 展示“检测到缺失字体，未执行替代”
3. 若 `font_replacement_applied = true`
   - 展示“已执行缺失字体替代”
   - 显示替代字体名称与替换样式数量

## 约束

1. 只在交付模块接入，不改前端其他模块。
2. 预检接口必须在正式提交前调用，不允许跳过。
3. 前端不得自行写死字体列表，必须使用后端返回的 `replacement_options`。
4. 若多文件中任一文件存在缺失字体，整批次都必须先完成用户确认。

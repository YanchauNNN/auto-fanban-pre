## 2. 系统当前定位

这是一个面向工程图纸交付的本地化处理平台，当前已经落地了四条主链：

- 交付主链：`DWG -> 拆图 -> PDF / 文档 / package.zip`
- 纠错主链：对 DWG 做词库扫描，输出 `report.xlsx`
- 翻版主链：按项目号词表做文本替换，输出翻版后的 `DWG`
- 管理业务线后端：账号、流程、工作量、归档

当前要特别注意的一点：

- **后端管理业务线已较完整**
- **主干前端仍以业务模块为主**

也就是说，这个项目当前不是“后端没做完”，而是“后端很多能力还没正式接到主干前端壳里”。

这是 Web API 外壳层，负责：

关键文件：

- `API/app/main.py`
- `API/app/runtime.py`

- `accounts/ auth/ workflow/ workload/ archive/ task_groups/`：管理业务线

### 3.4 `frontend/`

当前主干前端是 React + TypeScript + Vite 工作台。

已落地：

- 首页
- 业务模块
- 任务记录
- 详情页
- 出图 / 纠错 / 翻版弹窗

未落地：

- 登录壳
- 账号模块页面
- 工作量模块页面

### 3.5 `tools/`

这里放排错、验证、部署打包工具，不是生产主入口，但维护价值很高。

### 3.6 `storage/` 与 `documents_bin/`

- `storage/`：任务、任务包、运行态持久化
- `documents_bin/`：模板、词库、字体库、账号 CSV 等资源

## 5. 当前运行时总控

后端真实总控在：

- [API/app/runtime.py](../API/app/runtime.py)

核心职责：

- 校验上传参数
- 创建 `Job` 或 `TaskGroup`
- 写入持久化
- 投递后台执行
- 汇总详情与下载入口

### 5.1 当前任务模型

#### `Job`

执行层对象，代表一个真正进入流水线的任务。

当前主要类型：

- `deliverable`
- `audit_replace`

其中 `audit_replace` 在业务展示层会分化成：

- `audit_check`
- `audit_replace`

#### `TaskGroup`

业务层对象，代表一个由多个子任务组成的“任务包”。

当前主用场景：

- 出图 + 纠错
- 翻版 + 出图

### 5.2 当前真实创建方式

#### 纯出图

- `POST /api/jobs/batch`
- 返回单个 `deliverable job`

#### 出图 + 纠错

- `POST /api/jobs/batch`
- `run_audit_check=true`
- 返回一个 `TaskGroup`
- child:
  - `deliverable_main`
  - `audit_check`

#### 纯纠错

- `POST /api/jobs/audit-replace`
- `mode=check`
- 返回单个纠错任务

#### 纯翻版

- `POST /api/jobs/audit-replace`
- `mode=replace`
- `run_deliverable=false`
- 返回单个翻版任务

#### 翻版 + 出图

- `POST /api/jobs/audit-replace`
- `mode=replace`
- `run_deliverable=true`
- 返回一个 `TaskGroup`
- child:
  - `audit_replace`
  - `deliverable_main`

## 6. 交付主链

交付主链核心由 `backend/src/pipeline/executor.py` 编排。

当前典型流程是：

1. 接收上传 `DWG`
2. 转 DXF
3. 图框检测
4. 图签提取
5. A4 多页成组
6. 标题栏一致性修复
7. 切图 / 打印
8. 生成封面、目录、设计文件、IED
9. 打包 `package.zip`

### 6.1 前处理共享

当任务以 group 模式运行时，交付与纠错会共享前处理结果，例如：

- DXF
- frames
- sheet sets
- titleblock extracts

### 6.2 字体预检

当前主链在正式提交前已经加入字体预检。

前端入口：

- `POST /api/jobs/preflight-fonts`

后端返回：

- 文件级状态
- 缺失字体列表
- 按类型分组的替代候选
- 默认替代字体映射

### 6.3 打印样式

交付链现在已经把 `plot_style_key` 当成正式提交字段。

当前主干前端可选值：

- `red_wider`
- `same_width`
- `review_white`

运行时若未显式提交，则回退：

- `runtime_options.module5_export.plot.default_plot_style_key`

## 7. 纠错与翻版链

### 7.1 纠错（audit_check）

当前已经正式可用。

作用：

- 扫描 DWG 文本
- 根据词库匹配问题
- 输出 `report.xlsx`

### 7.2 翻版（audit_replace）

当前已经正式可用，不再只是概念方案。

作用：

- 根据 `source_project_no -> target_project_no` 做文本替换
- 输出翻版后的 `DWG`

并且已经支持：

- 仅翻版
- 翻版后继续走交付主链

相关说明文档请看：

- [翻版模块前端接入指导.md](./翻版模块前端接入指导.md)
- [archieve/翻版方案.md](./archieve/翻版方案.md)
- [archieve/翻版纠错方案.md](./archieve/翻版纠错方案.md)

## 8. 管理业务线

当前后端管理业务线已经具备以下能力：

- 登录认证
- 账号管理
- 人员补全
- `task-groups` 列表与详情
- submit / restart-submit
- workflow monitor / approve / repair
- workload 查询
- admin 配置

当前主干前端尚未把这套能力完整接出来。

### 8.1 一审当前真实规则

当前统一规则：

- 一审处理人只认 `ied_checked_by`
- `ied_discipline_leader` 继续保留，但不再作为一审回退来源

这条必须按当前代码理解，不能再照旧计划把两个字段强制写成同值。

## 12. 维护时的优先原则

### 12.1 先分层再改

遇到问题先判断属于哪一层：

- 上传协议
- 参数校验
- 图框 / 图签
- A4 多页
- 打印链
- 文档生成
- group / workflow / archive
- 前端展示

### 12.2 改字段先改源事实

新增或调整对外字段时，先改：

- `参数规范.yaml`
- 必要时再改 `参数规范_运行期.yaml`
- 然后改代码
- 最后改说明文档

### 12.3 不要把历史文档当现行代码说明

以下文档仍有参考价值，但默认属于历史材料：

- `documents/archieve/后端计划.md`
- `documents/archieve/PLAN-前端计划.md`
- 其他 `documents/archieve/*`

## 13. 推荐接手顺序

如果是第一次接手，推荐顺序：

1. 先读 [后端工作交接总说明.md](./后端工作交接总说明.md)
2. 再看 [参数规范.yaml](./参数规范.yaml)
3. 再看 [参数规范_运行期.yaml](./参数规范_运行期.yaml)
4. 然后读 `API/app/runtime.py`
5. 再读 `backend/src/pipeline/`、`backend/src/cad/`、`backend/src/doc_gen/`
6. 最后看 `frontend/src/`

如果是继续推进主干前端，推荐顺序：

1. 先接登录壳
2. 再接 task-group 视图
3. 再接 workflow / workload
4. 再接账号管理

# AI 机器人动作制作与验收

> 状态：Rive 桌面编辑器及 MCP 已连接，已建立原生骨骼小样；动作资产尚未制作完成，尚未替换主界面。
> 更新日期：2026-09-03。

## 一、目标与边界

本次采用“统一角色资产、骨骼动作、交互状态机、轨迹检查、视觉验收”的实现思路。不能以页面组件能够移动、功能测试通过或若干静态姿势正确，代替完整动作验收。

- 抽屉打开前后使用同一套机器人形象、比例、材质和骨架，不维护两套近似图案。
- 保留手臂的大幅运动能力，通过肩、肘、腕关节实现，不把手臂与身体合成不可活动的整体。
- 攀附时只露出头和少量倾斜身体，头部轻微倾斜，手部明确抓在抽屉边缘。
- 外部入口沿右侧上下拖动并保留位置；动画不能破坏已有位置记忆和视窗边界限制。
- 完整动作确认前，不替换主界面，不增加顶层模块入口，不改变业务 API。

## 三、动作制作顺序

| 阶段 | 动作意图 | 验收重点 |
| --- | --- | --- |
| idle | 右侧待机 | 身体完整，肩颈连接，表情支点正确 |
| approach | 从记忆位置就位 | 连续移动到可触及的抓握位置，不瞬间跳到顶部 |
| reach | 伸手抓边 | 先到达接触点，再建立抓握关系，身体不能先被遮没 |
| pull | 随抽屉打开 | 手掌锁定边缘，身体有跟随关系，不与抽屉各走各的轨迹 |
| cling | 倾身探头 | 少量躯干露出，头轻微倾斜，双手接触稳定 |
| tuck | 收身准备关闭 | 先收回头和躯干，抓握关系仍有效 |
| push | 随抽屉关闭 | 接触点与抽屉同步运动，遮挡随真实面板改变 |
| release | 松手回位 | 明确解除抓握，再回到记忆位置与待机姿态 |

上述阶段是动作意图，不是新的 setTimeout 列表。时间曲线应在动画编辑器中整体编排，先验收一个完整开关循环，再增加待机或大幅动作。

关闭动作不得仅通过复制开启动作的角度来实现。快速反向操作必须从当前姿态与进度继续，不重置回某个固定关键帧。

## 四、骨架与遮挡

1. 肩部随躯干运动，头部通过颈部支点连接躯干。通过平移头和身体制造探头效果时，不能破坏肩颈连接。
2. 上臂、前臂的长度来自资产绑定姿态；伸手使用 IK 目标和关节弯曲方向约束。不能依赖少数 FK 终点角度保证整个过程抓牢。
3. 天线支点放在头壳连接处，眨眼围绕眼部自身中心，不绕画布或头部原点旋转、缩放。
4. 手臂的贴图绘制关系应在躯干之上；抽屉对身体的遮挡与角色内部的绘制顺序分开处理。
5. 接触点以真实抽屉左边缘和顶部计算。宽度、高度、视窗变化时，不能继续使用独立固定的 top 值。
6. 面板必须是实际遮挡物，不能依赖白色矩形盖住身体。手指前景与身体后景若分通道绘制，必须来自同一姿态快照，不能独立播放。
7. Rive 与 DOM 的裁剪、圆角、透明度组合必须在独立场景中验证后再确定实现方式；.riv 文件本身不自动理解网页抽屉的位置和遮挡。

## 五、资产交付要求

- 可编辑源文件与对应的 .riv 文件，记录编辑器版本、导出日期、运行库版本。
- 同一角色资产至少具有上述一个完整开关循环，不以多张不一致的素材切换。
- 提供抓握标记、肩颈两侧连接标记、肘腕标记，以及供检查的头部和身体轮廓极值点。
- 两侧连接标记应分别挂在各自部件上。将同一个坐标复制为两个标记会掩盖断开问题。
- 对需要从运行库读取的标记显式导出名称；具体数据绑定与时间控制接口在制作阶段验证。
- 运行文件、贴图、字体和 WASM 必须随程序本地打包，不依赖外部 CDN 才能显示。
- 动画运行故障不得阻断 AI 入口和键盘操作；失败状态应使用明确的静态入口降级。

## 六、轨迹检查器

检查器位于 `frontend/src/features/ai-chat/motion-review/`，不被主界面导入，不需要启动业务后端。命令行位于 `tools/review_mascot_motion.mjs`。

在项目根目录使用 Node.js 24 或更新版本运行：

```powershell
node tools/review_mascot_motion.mjs <trace.json> <policy.json>
```

输入轨迹、检查策略均通过 JSON 文件提供。检查器不修改输入、不访问网络，不在代码中内置验收阈值。这里是离线前端验收输入，不替代或扩充现有三份后端参数规范。

### 1. 轨迹数据

类型定义见 `motionTrace.ts`。

- `schemaVersion`：当前为 1。
- `source`：`browser-capture` 或 `synthetic`。这是采集方的来源声明，不是检查器证明真实性的凭据；人工构造和单元测试数据必须标记为 `synthetic`。
- `viewport`：采样视窗的 CSS 像素宽高。视窗尺寸改变后分开采集，不混入同一条轨迹。
- `frames`：至少三个连续采样点，包含 `timeMs`、`phase`、`actorScale`、`drawer` 和 `landmarks`。
- `timeMs`：单调递增的实测时间，不使用阶段序号充当时间。
- `actorScale`：每个资产设计单位对应的 CSS 像素数，只支持均匀缩放。
- `drawer`：从实际面板测得的 `left/top/width/height`，不是角色自行计算的目标位置。
- `landmarks`：命名标记的实际屏幕坐标，不能使用尚未绘制的目标姿势坐标代替。

### 2. 检查策略

| 字段 | 含义 |
| --- | --- |
| sampleGapMs | 允许的最大采样间隔，超过即判定采样无效 |
| minimumDurationMs | 本次规定动作的最短采集时长 |
| requiredPhases | 必须覆盖的动作阶段；完整循环不能只填 cling |
| trackedLandmarks | 必须逐帧提供的标记 |
| connections | 两部件连接处的独立标记对 |
| bones | 骨段标记及资产绑定长度 |
| contacts | 抓握标记、生效阶段、相对抽屉左上角的设计单位偏移 |
| connectionGapPx / contactErrorPx | 连接与抓握的允许误差，单位为 CSS 像素 |
| boneLengthRelativeError | 骨段长度相对误差 |
| speedPxPerSecond | 标记的屏幕速度上限 |
| accelerationPxPerSecondSquared | 标记的屏幕加速度上限 |
| viewportMarginPx | 标记距离视窗边界的最小内边距 |

阈值应根据最终角色尺寸和批准的动作校准，不将某个示例数值称为行业标准。策略非空校验不能代替策略本身的人工审查。

### 3. 结果解释

- `invalid`：输入、规则、阶段覆盖或采样完整性不满足条件，或计算产生非有限数值，退出码 2。
- `violations`：发现几何或运动阈值问题，逐条给出帧号、时间、标记、实测值和阈值，退出码 1。
- `within-geometric-limits`：在给定规则与样本内没有发现超限，退出码 0，**不等于动作验收通过**。
- `visualReviewRequired` 始终为 true，不输出“自然度评分”或“整体动画通过”。

### 4. 明确不覆盖的内容

当前检查器不采集浏览器帧、不生成 Rive 资产、不判断贴图美感、不进行像素级遮挡检测。标记未越界也不能证明完整贴图未被裁切；残影、轮廓和可见像素仍需另行核查。

关节弯曲方向、眼部支点、动作意图、阶段顺序和快速中断恢复也需在资产场景中检查，不能以几何报告替代。

## 七、完整验收

1. 按正常速度和慢速完整回放，叠加骨架、接触点、轨迹线及前后帧残影。
2. 从顶部、中部、底部记忆位置开始，检查就位、打开、关闭、回位；检查连续点击和途中反向。
3. 在桌面、窄窗口与移动端分别检查，包含抽屉尺寸调整与减少动态效果设置。
4. 真实采样不得关闭 CSS 过渡、冻结定时器或用目标姿势替代中间帧。离线求值结果单独标为模拟数据。
5. 保存采样 JSON、策略文件、几何报告、正常速度录像和失败帧。记录实际视窗、缩放、资产版本与运行库版本。
6. 视觉验收确认不脱节、不滑手、不穿面板、不闪烁，动作意图明确后，再接入正式主界面和部署包。

# 翻版模块前端接入指导

## 目标
- 当前后端已经完成翻版 MVP。
- 前端本轮只需要接通现有交互，不需要改后端逻辑。
- 本轮仍然只做前端接入，不做块替换 UI。

## 后端能力现状
- 接口：`POST /api/jobs/audit-replace`
- 支持模式：
  - `mode=check`：纠错
  - `mode=replace`：翻版
- 翻版支持两种运行方式：
  - `仅翻版`
  - `同步出图和翻版`
- 真实后端烟测已验证：
  - 输入 `20261NH-JGS51-B合并版.dwg`
  - 从 `2026 -> 2016`
  - 再用 `2016` 跑纠错
  - `findings_count = 0`

## 提交接口

### 1. 仅翻版
- 请求：
  - `POST /api/jobs/audit-replace`
  - `Content-Type: multipart/form-data`
- 表单字段：
  - `mode = replace`
  - `params_json = JSON.stringify({...})`
  - `files[] = dwg 文件`
- `params_json` 结构：

```json
{
  "source_project_no": "2026",
  "target_project_no": "2016",
  "target_island_no": "1",
  "run_deliverable": false
}
```

### 2. 同步出图和翻版
- 请求仍然是：
  - `POST /api/jobs/audit-replace`
- `params_json` 结构：

```json
{
  "source_project_no": "2026",
  "target_project_no": "2016",
  "target_island_no": "1",
  "run_deliverable": true,
  "deliverable_params": {
    "...": "当前出图表单已有参数，原样提交"
  }
}
```

- 这里的 `deliverable_params` 就是当前交付处理表单已经收集好的配置。
- 后端会先翻版，再把翻版后的 `DWG` 作为出图输入继续执行。

## 提交校验
- 后端校验规则：
  - `source_project_no` 必填
  - `target_project_no` 必填
  - `source_project_no != target_project_no`
  - `source_project_no=2016/1916` 时，`source_island_no` 必填
  - `target_project_no=2016/1916` 时，`target_island_no` 必填
  - `run_deliverable = true` 时，`deliverable_params` 需要满足现有出图参数校验
- 错误仍走现有 `422` 结构：

```json
{
  "detail": {
    "upload_errors": {},
    "param_errors": {
      "target_project_no": ["must_differ_from_source_project_no"]
    }
  }
}
```

## 列表与详情

### 1. 列表
- 翻版单任务：
  - `task_kind = audit_replace`
  - `job_mode = replace`
- 翻版+出图 group：
  - group 下会有两个 child：
    - `audit_replace`
    - `deliverable`

### 2. 单个翻版任务 detail
- `GET /api/jobs/{job_id}`
- 关键字段：

```json
{
  "task_kind": "audit_replace",
  "job_mode": "replace",
  "artifacts": {
    "report_available": true,
    "report_download_url": "/api/jobs/{job_id}/download/report",
    "replaced_dwg_available": true,
    "replaced_dwg_download_url": "/api/jobs/{job_id}/download/replaced"
  },
  "replace_summary": {
    "replacement_count": 51,
    "skipped_count": 0,
    "affected_drawings_count": 10,
    "source_project_no": "2026",
    "target_project_no": "2016",
    "top_replaced_texts": ["2026", "2026XNI-JGS02", "XZ"],
    "top_internal_codes": ["20261NH-JGS51-001"]
  }
}
```

### 3. 翻版+出图 group detail
- `GET /api/jobs/{group_id}`
- group `artifacts` 可能同时包含：
  - `replaced_dwg_download_url`
  - `report_download_url`
  - `package_download_url`
  - `ied_download_url`

## 下载按钮
- 翻版任务需要展示：
  - `replaced.dwg`
  - `report.xlsx`
- 当前没有单独的 `report.json` 下载路由，前端这轮只需要接 `report.xlsx` 即可。
- 如果是翻版+出图 group，还需要继续展示：
  - `package.zip`
  - `IED计划.xlsx`

## 推荐前端交互

### 1. 主模式
- 在现有“纠错/翻版”切换里，翻版模式提交到 `/api/jobs/audit-replace`。
- 不要再弹“接口未开放”。

### 2. 翻版表单字段
- 源项目号：`source_project_no`
- 来源机组/岛号：`source_island_no`
  - 所有需要选择的项目统一显示为 `X号机组/岛`
- 目标项目号：`target_project_no`
- 目标机组/岛号：`target_island_no`
  - 所有需要选择的项目统一显示为 `X号机组/岛`
- 上传 `DWG`
- 选项：
  - `仅翻版`
  - `同步出图和翻版`

### 3. 与出图联动
- 当用户选“同步出图和翻版”时：
  - 继续显示现有出图配置区
  - 提交时把出图配置整体塞进 `deliverable_params`
- 当用户选“仅翻版”时：
  - 不提交 `deliverable_params`

### 4. 本地配置保存
- 需要纳入当前草稿/预设保存的字段：
  - `source_project_no`
  - `source_island_no`
  - `target_project_no`
  - `target_island_no`
  - `run_deliverable`
- 如果当前实现里翻版页已经复用了出图草稿对象，则直接把这些字段并入原有草稿结构即可。

## 展示建议

### 1. 翻版完成弹窗/摘要
- 可以直接展示 `replace_summary`：
  - 替换数量
  - 受影响图纸数
  - 源项目号
  - 目标项目号
  - 高频替换文本

### 2. Group 展示
- 如果 group 同时包含翻版和出图：
  - 保留当前 group 卡片
  - child 状态可继续按现有模式显示
  - 下载区增加 `replaced.dwg`

## 不要做的事
- 不要在前端自己做词库替换或预处理。
- 不要在前端自己推断翻版映射。
- 不要把纠错和翻版做成同一个提交开关。
- 不要改 `frontend` 里现有出图参数名和出图提交结构，翻版+出图只是在外层包一层 `deliverable_params`。

# 前端任务书：字体替代与多页联调

更新时间：2026-04-02

## 1. 目标

本任务书只覆盖两条需要前端配合联调的后端能力：

1. 字体预检与按类型字体替代
2. 普通图纸“同编码多页”结果展示

本轮不要求前端修改 CAD 算法相关逻辑，不要求改 A4 多页 `sheet_set` 展示规则。

## 2. 真实接口口径

### 2.1 上传后先做字体预检

前端在用户上传 DWG 后，先调用：

- `POST /api/jobs/preflight-fonts`

上传字段：

- `files[]`

等待态文案：

- `正在执行字体搜索...`

响应里与前端直接相关的字段：

- `files`
- `replacement_options`
- `replacement_options_by_kind`
- `default_replacement_font`
- `default_replacement_fonts`
- `requires_confirmation`

### 2.2 字体替代现在是按类型传入

正式创建任务时，前端需要把字体替代参数写进 `params_json`。

兼容旧字段：

- `font_replace_policy`
- `font_replacement_font`

本轮应优先使用的新字段：

- `font_replacement_fonts`

结构示例：

```json
{
  "font_replace_policy": "replace_missing",
  "font_replacement_fonts": {
    "ttf": "simsun.ttc",
    "shx": "simplex.shx",
    "bigfont": "hztxt.shx"
  }
}
```

规则：

- `ttf` 缺失必须选 `ttf`
- `shx` 缺失必须选 `shx`
- `bigfont` 缺失必须选 `bigfont`
- 不要再把所有缺失字体都压成同一个全局字体

如果只有一种缺失类型，也允许只传这一种类型。

### 2.3 默认值展示

后端已经返回：

- `default_replacement_font`
- `default_replacement_fonts`

前端应直接用它们作为默认选中值，不要自己猜默认字体。

## 3. 曹恒恒这类缺 TTF 的展示要求

这类图纸的问题不是“缺 SHX”，而是缺 `ttf`。前端不能再只展示 SHX 候选。

展示要求：

- 预检结果按 `kind` 分组显示
- 每个缺失字体条目至少展示：
  - `style_name`
  - `font_name`
  - `bigfont_name`
  - `kind`
  - `used_in_block`
- 如果 `kind = ttf`，下拉框必须绑定 `replacement_options_by_kind.ttf`
- 如果 `kind = shx`，下拉框必须绑定 `replacement_options_by_kind.shx`
- 如果 `kind = bigfont`，下拉框必须绑定 `replacement_options_by_kind.bigfont`

不要再把所有缺失字体共用一个下拉。

## 4. 韩冰这类同编码多页展示规则

适用范围：

- 普通图纸 PDF/DWG 物理输出
- 不适用于 A4 `sheet_set`

### 4.1 目录展示

目录中：

- 同编码多页仍然只显示一行
- 页数列显示总页数，例如 `2`

### 4.2 文件列表展示

物理文件现在会拆成多份，但命名规则改成：

- `状态X@Y`

示例：

- `JD2RSG11005B25C42SDACFC1@2 (20162RS-JGS03-005).pdf`
- `JD2RSG11005B25C42SDACFC2@2 (20162RS-JGS03-005).pdf`
- `JD2RSG11005B25C42SDACFC1@2 (20162RS-JGS03-005).dwg`
- `JD2RSG11005B25C42SDACFC2@2 (20162RS-JGS03-005).dwg`

前端不要再按旧的 `-p1of2` / `-p2of2` 去解析。

### 4.3 文案解释

任务详情页或结果页建议解释为：

- `同编码多页：目录合并为一行，物理文件按页分别输出`

## 5. 错误展示要求

### 5.1 字体预检失败

如果 `preflight-fonts` 某个文件返回：

- `status = failed`

则不要继续提交任务，直接展示该文件的错误信息。

### 5.2 缺失字体未确认

如果存在：

- `status = missing_fonts`

则不要直接进入创建任务成功态，必须先让用户选择替代字体。

### 5.3 任务详情里的字体说明

如果任务详情里有：

- `font_preflight_summary`
- `missing_fonts_detected`
- `font_replacement_applied`
- `replacement_font`
- `replacement_fonts`
- `replaced_style_count`

前端应展示为：

- 是否检测到缺失字体
- 是否已执行替代
- 替代了多少个样式
- 每种类型最终使用了什么替代字体

## 6. 前端 smoke checklist

### 6.1 曹恒恒字体链

样本：

- `19076RS-JGS01(C).bak`

验收：

- 上传后先出现 `正在执行字体搜索...`
- 能看到 `ttf` 类型缺失字体
- 替代项按类型展示
- 任务成功后结果页能看到字体替代摘要

### 6.2 韩冰同编码多页

样本：

- `Drawing2.dwg`

验收：

- 创建任务成功
- 结果页里 `005` 的物理文件名是 `CFC1@2` / `CFC2@2`
- 目录中 `005` 只出现一行
- 该行页数为 `2`

### 6.3 既有基线

前端联调时不要回退这些已修好的行为：

- A4 多页 `sheet_set` 仍按原逻辑展示
- 字体预检通过时直接进入出图配置页面
- 字体预检未通过时进入字体替代页面
